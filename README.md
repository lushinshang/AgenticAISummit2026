以及一個可離線瀏覽、整包搬移不會失效的靜態網站。

## 一、專案目的

大會兩天七個舞台、43 小時錄影，官方只提供英文自動轉錄稿。這種稿子有三個問題讓它幾乎不能讀：

1. **沒有分節**：整場連成一片，找不到某位講者講在哪裡
2. **沒有講者**：文字段落看不出誰在說話，座談會尤其混亂
3. **轉錄品質參差**：人名大量拼錯（Jianfeng Gao → "Zhang Gao"）、有整段全小寫無標點、有時段完全沒錄到

這個專案要解決的就是這三件事，並在過程中堅持一條原則：**寧可標註「這裡聽不清楚」，也不編造內容**。

字數一律只計中文字，不含空白與標點——同一份文稿用字元數會多出三成，容易誤導。

### 網站結構

```
index.html                     入口頁：兩天七舞台共 14 個連結
├─ day1_zh/html/               8 份：4 舞台 ×（全文／導讀）
└─ day2_zh/html/               6 份：3 舞台 ×（全文／導讀）
```

每份全文：依議程切節，每節標時間、場次、講者姓名職稱與講題；每次發言前標發言者，換人處切段；
錄音不清處標 `[?]`（滑鼠移上去有說明），整場缺漏用獨立區塊寫明「現場錄影未涵蓋此時段」。

每份導讀：逐場梳理講者的核心主張與論點推進，不是逐句摘要；篇幅依內容深度決定。
每舞台挑 3–4 個代表議程配一張資訊圖（桌機 16:9 與手機 9:16 兩版，`<picture>` 自動切換，點圖放大）。

## 三、作業歷程

三個階段，各自獨立提案、實作、驗收。

### 階段一：Day 1（4 舞台 42 場議程）

**素材**：8 個 SRT，27h27、英文約 22.8 萬字。

| # | 步驟 | 做法 | 產出 |
|---|---|---|---|
| 1 | 清洗轉錄稿 | `clean_srt.py` 濾填充語、合併片段 | `cleaned/*.jsonl` |
| 2 | 解析議程 | `parse_agenda.py` | `agenda.json`（姓名職稱講題的權威來源） |
| 3 | **判讀議程切點** | **8 個 subagent 語意判讀** | `segments/*.json`（42 個切點） |
| 4 | 查核切點 | `verify_segments.py` → `fix_segments.py` | 修掉 off-by-one |
| 5 | 切翻譯區塊 | `make_chunks.py`，每塊 ≤5000 英文字 | `chunks/*.json` |
| 6 | **翻譯** | **63 個 subagent**，規格 `TRANSLATE_SPEC.md` | `zh_chunks/*.md` |
| 7 | 合併全文 | `normalize_punct.py` → `build_transcript.py` | `transcript/*.md` |
| 8 | **導讀** | **37 個 subagent**，規格 `GUIDE_SPEC.md` | `guide_chunks/*.md` |
| 9 | 資訊圖 | `gen_images.py` + codex `image_gen` | 28 張 |
| 10 | 轉檔與入口頁 | `md2html.py`、`build_index.py` | 8 份 html + `index.html` |

**為什麼切點要用 subagent 而不是正則**：試過純正則比對議程表的講者姓名，多位講者 0 命中——
因為轉錄把姓名拼錯了。改成給 subagent 看議程表與轉錄稿，靠語意判斷「這裡換場了」，才做得準。

**驗收**：派未參與製作的 fresh agent 獨立驗收，分「網頁與連結」「翻譯忠實度」「導讀品質」三面向，
三輪共修掉 12 項問題。最嚴重的一項機器查核抓不到：導讀把某公司部落格才發布的職業選手勝績，
錯掛成該公司《Nature》封面論文的成果，還把「曾排名」寫成現任——只有回原文比對才會發現。

### 階段二：Day 2（3 舞台 28 場議程）

**素材**：6 個 SRT，16h25、英文約 14.9 萬字（Day 1 的 66%）。

流程沿用階段一，把 `day1_zh/tools/` 整包複製後改。但遇到四個 Day 1 沒有的狀況：

1. **Atlas 上午 43% 是全小寫無標點轉錄**（`all right welcome everyone day two atlas...`）。
   影響切點判讀（沒有大寫姓名可辨識）與翻譯（沒有句界）。派工 prompt 明確要求譯者自行判讀句界、
   輸出必須是通順有標點的中文，實測品質良好。
2. **`clean_srt.py` 的合併規則失效**：原本要求「句尾有標點才斷段」，遇到無標點來源就一路併下去，
   實測產生單一段落 64,443 字元。加上與內容無關的硬上限（超過 1400 字元強制斷）才正常。
3. **三處講者異動**：David Hsu 缺席由 Dan Klein 代打、Navrina Singh 由 Eric Aldana 代打、
   Christopher Petrillo 缺席。一律據實記錄，不硬套議程表。
4. **四場無錄影**：Plenary 開幕致詞、休息與交流酒會未錄到，Compass 下午前 11 分半空白。
   全部標明，不編造。

### 階段三：發言者標註（兩天七舞台，998 處）

前兩階段的成品在段落層級看不出誰在說話，座談會尤其嚴重。這一階段補上。

**Day 2（703 處）**：43 個區塊各派一個 subagent 判讀，材料是「議程表講者名單＋英文原文＋譯文逐段並排」，
規格見 `tools/SPEAKER_SPEC.md`。

做試點時發現一件關鍵的事：**座談會有 59% 的段落，內部就換過人**——主持人問完、與談人立刻接話，
被轉錄併成同一段。只在段首標一個名字，等於把後半段的話掛到別人頭上，比不標更糟。所以規格改成
**換人處必須切段**。試點區塊 39 段切成 71 段。

**Day 1（295 處）**：由外部 AI 產出後移植。**不是直接採用**——那版把同一位講者的連續段落全部併成一段，
atlas 最長一段 8,499 字、21 段超過 2000 字，網頁上是一堵沒有換氣點的字牆。所以只取「誰在哪裡開始講」，
用指紋比對套回原本的段落結構，移植後最長段降到 1,288 字。

過程中另外修掉：五個只有名字的講者補全名（`Peter` 是 Peter Steinberger 不是 Peter Stone）、
七處漏切造成的掛錯人（「Don」是 Dawn Song 的轉錄失真、「謝謝你，Dan」的 Dan 是 Dan Roth）、
2,646 個會把段落打散的 `<br>`。

**零改動查核**：`verify_speakers.py` 把標註前綴拿掉、去掉所有空白後與原譯文比字串，
**一個字不同就退回重做**。這條防線攔下過真實的事故——某次外部 AI 產出的版本，
有一句中文被改寫成了印地語（`因為只會示範一次。` → `क्योंकि यह केवल एक बार प्रदर्शित किया जाएगा।`）。

## 四、技術決策與理由

| 決策 | 理由 |
|---|---|
| 議程切點用 subagent 語意判讀，不用正則 | 轉錄姓名大量拼錯，正則比對多位講者 0 命中 |
| 姓名一律以議程表為準 | 轉錄常拼錯（Sanja Fidler → "Sonia"、Morrone → "Maroney"） |
| 但報幕與自我介紹以錄音為準 | 代打講者議程表上沒有；硬套議程表反而錯（Postman 那場報幕唸的是 Rick Crawford） |
| 判不出真名就用代號，不猜 | 「新創焦點」轉錄的人名明顯失真（同段出現「Paisa News」），整場改用公司代號 |
| 所有 subagent 產出都要能機器查核 | 三支 `verify_*.py` 分別查段落短少、大陸用語與簡體字、殘留包裝標籤、譯文改動 |
| 缺漏用獨立可見區塊，不用 HTML 註解 | 註解在網頁上完全看不見，57 處誠實標註等於不存在 |
| 資訊圖用 `height:auto` 不裁切 | codex 產出的比例是 0.40–0.56 不等，寫死 `aspect-ratio` + `cover` 會裁掉標題 |
| 全站相對路徑 | 整包搬到任何路徑或網域都不會失效 |
| 圖片轉 WebP | 48 張 85.5 MB → 11.4 MB（減 87%），文字清晰度目視無損 |

## 五、踩過的坑

| 坑 | 症狀 | 對策 |
|---|---|---|
| 轉錄人名大量拼錯 | Jianfeng Gao → "Zhang Gao" | 一律以議程表為準，寫進派工 prompt |
| 影片時間 ≠ 議程掛鐘時間 | 開頭數十分鐘都是 `Thank you.` | 切點靠語意判讀，不用時間差推算 |
| subagent 回報「已照字面處理」但其實改了 | 2004 被譯成 2024 | 回報要交叉核對原文，不能只信 agent 說法 |
| subagent 漏刪外層包裝標籤 | 殘留 `</content>`，轉 html 後標籤不對稱 | 查核器加 `WRAPPER_TAG` 規則 |
| Python 腳本缺 `main()` 保護 | import 時整份跑完並 `sys.exit`，呼叫端靜默失效 | 主體一律包 `if __name__ == "__main__"` |
| 用 `startswith` 判斷條列 | 誤把 `**講者名：**` 開頭的段落當條列刪掉 | 改用要求符號後有空白的正則 |
| 合併規則依賴內容特徵 | 無標點來源讓整份併成一段（64,443 字元） | 一定要配一個與內容無關的硬上限 |
| 複製腳本後改「共用常數」 | `build_index.py` 的 `STAGES` 一改，Day 1 的 Nexus 整個消失 | 產出橫跨多資料集的腳本，清單要跟著各自的資料走 |
| 硬編的文件標頭 | 複製後只改 `STAGES`，Day 2 六份成品全自稱 Day 1 | 查核器只驗結構與用語，沒人驗「這份文件說自己是哪一天」 |
| 姓名內含括號 | `Yuan (Emily) Xue (Scale AI…)` 被切成 `Yuan` | 改用括號配對解析，不能用正則 |
| `aspect-ratio` + `object-fit:cover` | codex 產圖比例不固定，標題被裁掉 | 用 `height:auto` 依原圖比例 |
| codex image_gen prompt 太長 | 連續逾時，錯誤只回 `timeout` | 壓在十行內，多項目用分號壓成一行 |
| imagegen 的 `topic` 與 `point` 不同步 | 只改標題寫「六個角度」，`point` 仍寫「八位講者」，圖上打架 | 兩個欄位要一起改 |
| 外部 AI 產出的「零改動」不可信 | 一句中文被改寫成印地語 | 一律跑字串層級的零改動查核 |

更完整的記錄在 `~/projects/ops/LESSONS.md`。

## 六、重現方式

### 目錄結構

```
.
├── index.html                入口頁（build_index.py 產生）
├── Day1Agenda.txt            官方議程繁中版（唯讀，姓名與譯名的權威來源）
├── Day2Agenda.txt            同上，Day 2
├── day1_zh/
│   ├── transcript/           4 份繁中全文 md
│   ├── guide/                4 份主題式導讀 md
│   ├── html/                 8 份 html + images/ 28 張 WebP
│   └── tools/                19 支腳本、規格檔與中繼資料
└── day2_zh/                  同上結構（3 舞台、20 支腳本）
```

非網站內容集中在 `_source/`（原始英文轉錄稿與大會官網離線備份），都是第三方內容，不隨本專案發布；說明見該目錄的 README。

### 重建成品

```bash
# 改完 zh_chunks/、guide_chunks/ 或 speaker_tagged/ 後跑這串
DAY=day2_zh          # 或 day1_zh
python3 $DAY/tools/build_transcript.py
python3 $DAY/tools/build_guide.py
python3 $DAY/tools/md2html.py
python3 day2_zh/tools/build_index.py    # 入口頁兩天共用，一律跑這支

# 查核
python3 $DAY/tools/verify_zh.py          # 段落短少、大陸用語、簡體字、殘留標籤
python3 $DAY/tools/verify_guide.py       # 導讀篇幅比例、禁用詞
python3 $DAY/tools/verify_speakers.py    # 發言者標註：譯文零改動

# 本機預覽
python3 -m http.server 8000
```

### 中繼檔保留策略

| 目錄 | 可否重生 | 說明 |
|---|---|---|
| `segments/` | **不能** | subagent 語意判讀的切點，**務必保留** |
| `zh_chunks/` | **不能** | 翻譯產物，要改文字時的正確入口 |
| `guide_chunks/` | **不能** | 導讀產物 |
| `speaker_tagged/` | **不能** | 發言者歸屬，來源已刪，刪了要整批重做 |
| `chunks/`、`sections/` | 可 | 對應腳本可重生 |
