在這個案例裡，就是要更快地修補。好，這裡有一堆彼此相連的元件，我要描述一個真實的環境，接下來我會切換畫面，實際連到一個真正的環境。有多少人用過像 N8N 或 ActivePieces 這樣的工作流程工具？聽過這些東西嗎？好。知道流程圖是什麼嗎？好，在企業裡常常是這樣：「流程是什麼？」喔，就是 Bob 從 Mary 那邊拿到資料夾，交給 Janet，影印三份，諸如此類。這些事情真的很花時間，會替原本應該順暢的業務流程增加複雜度、增加摩擦、增加卡頓感。所以在這個案例裡，我要秀給大家看幾個元件。

第一個就是視覺化的部分。想成是工作流程，想成是流程圖：從一個觸發點（trigger）開始，然後一步一步往下走。為什麼你們要從這裡開始很重要？因為它能幫你把業務流程視覺化，也方便你跟別人解釋。而那些連接的部分，也就是「邊」，正是你能找到最佳化機會的地方，對吧？延遲往往就藏在這些銜接處，等一下我會秀給大家看。我們接下來會連進一個 SUSE 的產品。這裡跑的所有東西，就是那些被連接在一起的基礎設施元件。最底層是 Linux 作業系統：SUSE Linux Enterprise 以及它的各種變體。對那些跑 SAP 的人來說，在大型企業裡，他們非常在意永遠不要關機、永遠不要重開機。

但這要怎麼跟「我們得修補東西、有嚴重的 CVE、零時差漏洞」這件事平衡呢？要怎麼做到？SUSE 有一項技術叫做「即時修補（live patching）」，很誇張，我們可以在不重開機的情況下，更新正在跑的核心（kernel），更新 OpenSSL 函式庫，更新 glibc。所以 SAP 可以一路運行長達一年，而且完全在支援範圍內，就是這麼厲害。所以無論是使用者空間還是核心空間，這些即時修補都是這整塊拼圖的一部分。我們還有一項技術叫做 Multi-Linux Manager，做什麼用的？光看名字就知道，它管理多種 Linux 發行版。這是一個以 pub-sub（發布—訂閱）為架構的框架，而不是像 SSH 連線那樣，最後把控制節點壓垮，大家可能會想到 Ansible，對吧？

我們用的是 pub-sub，有點像 ZeroMQ 那種訊息代理（broker）與訂閱者的架構。透過這些格式，我們能直接告訴整個環境裡的每一台機器「你需要修補了」，而不用每次都再開一個新的 SSH 連線。它還是用加密，只是是非對稱式的，所以能擴展到任何規模。我們有客戶管理著八萬台不同類型的 Linux 主機，全部都在分層管理之下。這一整套元件，能讓你修補得更快，因為你是在並行處理，對吧，「平行化（parallelization）」，如果這個詞真的存在的話——不知道，大學生們，幫我確認一下（笑）。但重點是，一旦你能同時處理更多東西，那就會變成頻寬的問題，而那是可以花錢解決的問題。

我需要更快的交換器，我需要更大的頻寬投資。然後你能跑多快，就取決於你的網路能讓你跑多快。好，Multi-Linux Manager 有自己的 MCP 伺服器，哇。SUSE Linux Enterprise 也有 MCP 伺服器連接能力。這些全都是把整套東西縫合在一起的拼圖之一，等一下會再細講。我們也有一個「大腦」，也就是代理（agentic）的部分——歡迎來到這場高峰會。我們讓你自己帶模型來，跑自己的推論。再加上我們龐大的技術堆疊：Linux、Kubernetes、用來管理的 Rancher、虛擬化，貓狗一起養也不會亂（笑），而這一切都來自單一供應商，而且是開源的，對吧？所以你現在就可以直接上手試用。等你到有企業版本的大公司工作時，用的其實是同一套東西，就是我在自己桌機上學到的那套。

而且我完全不用付錢。如果你聽過 Docker Desktop，對，我可以寫一個 Dockerfile，部署它，然後看，我有一個容器了，很酷。Rancher Desktop 也是類似的東西。但現在我們談的是企業級 Kubernetes、YAML 檔案、Fleet、CI/CD 流水線，這些才是我們真正用來部署、使用可規模化 AI 工作負載的東西，對吧？所以接下來要給大家看一些免費的東西。每一層都會開放出一個新的工具，但我們會透過單一的工作流程，把它們全部串在一起。

好，話不多說，我們直接進入 N8N，帶大家看看它長什麼樣子。這也是一個容器化的工作負載。耶，開源，算是「有點」開源啦。N8N 可以免費用，除非你想拿它來賺錢，那他們就會反過來跟你收錢，好嗎（笑）？但在那之前，重點是：我要怎麼把一個複雜的工作流程分享給我的朋友、同事、還有主管，讓大家理解，嘿，摩擦點就在這裡，這裡就是我們該專注的地方。我們等一下會聊聊那個工具。好，我們先看第一個 N8N 畫面。不對，是另一個 N8N 畫面，另外那個、另外那個。

我來處理一下，就是些電腦技術上的小問題（笑）。好了。

我們打開第一幕。這基本上是 N8N 的空白畫布，啟動時大概就只有一個工作區。想想你會想從哪裡開始一個工作流程，用流程圖的說法來講，就是一開始那個寫著「從這裡開始」的大方塊，我們現在就在那裡。觸發器（trigger）會啟動某件事，觸發器可以是時間型觸發器，也可以是 webhook 觸發器，任何能啟動這個流程的東西都算。這些觸發器我可以手動點擊，它做的事情就是把流程沿著這條管線啟動起來。接著我想加入節點（node），這個案例裡，我們會先放一個設定用的區塊（config bucket），定義好網址、目標，並把它們轉成變數格式，讓它能沿著整條鏈傳遞下去。

這樣它就會從環境變數裡把值抓出來，這是個很好的做法，不用把我的權杖（token）、密鑰、API 金鑰之類的東西直接暴露給所有人看。所以我們就先從手動觸發器開始，看看它長什麼樣子。一樣，我可以直接執行它。

我點一下按鈕，完成，這一樣只是啟動流程而已。很棒的地方在於，接下來你可以把東西連接起來，這些叫做「節點（node）」，這就是所謂的「邊」連接。我們進到下一步。了解，觸發器的部分，我可以放一個時間型觸發器。有多少人用 Gmail？好。有多少人搭配用 Google Docs？也就是說你們在那個生態系裡。有多少人用 Teams（微軟的）？好，那你們就是用那個生態系。真正酷的地方是，你的觸發器可以是電子郵件。假設你在 Google 的生態系裡……

所以我可以把它連接到各種不同類型的觸發器：有人把文件丟進資料夾、有人做了更新、有人寄了封信、有行事曆事件進來。想想我們平常打造代理時會用到的所有觸發條件，這裡全都以預先做好的小節點呈現，對吧？你得提供憑證、掛勾（hook），這些就是你會藏在設定裡的東西，但大概能了解概念了吧，就是輸入與輸出。在那個大架構圖裡，那個裡面有個大腦之類東西的大方塊，我們會把它接到 Slack，因為又快又簡單。我原本想用 Telegram、Botfather 那一套，但就讓你自己盡情發想吧。

節點都在這裡。好，接下來，進到第一幕，Dana。好，這裡是設定的部分，我秀給大家看裡面是什麼。可以看到這些 JSON 標籤，這些都是在定義網址，它們是從我後端執行器（runner）上的環境變數抓出來的，一樣是為了把機密資訊隱藏起來。接下來，它會做這個「MCP 機群掃描（fleet scan）」，我等一下就會執行。這一步實際上會呼叫 MCP 伺服器，也就是 Multi-Linux Manager 的一部分，跟所有被管理的 Linux 主機對話。等一下也會示範給大家看。它會呼叫那個 MLM 的 MCP 伺服器，詢問機群的狀態。

那我來執行一下，可以看到，一樣，先觸發，把所有變數塞進設定裡，然後它就跑出去了，實際上是透過那個 MCP 伺服器和我的基礎設施對話，把所有細節都找出來，包括修補的細節，還有所有能幫我排優先順序的資訊。記得，如果你只有四小時的時間窗，卻有一萬台裝置，而你原本連三十小時、三十天都修補不完，那現在被壓縮成這樣，你該跟你的資安長討論的，就是怎麼替重要的修補程式排優先順序。有多少人會看 CVE 分數，像 CVSS 9.5 這種，就覺得「這一定要修」？有多少人是照 CVE 分數，或照 CVE 目錄來排序的？CVE 目錄是什麼？不是《小鬼當家》裡的那個 Kevin，對吧（笑）。

它是目前實際在野外、真正正被利用的已知漏洞目錄，也就是已知的漏洞利用與弱點清單，對吧？就是一個目錄。我會建議大家去看看，嘿，這個漏洞是不是正在被實際利用，相對於一個 CVSS 分數 9.2、但需要 root 權限、終端機存取權，或實體存取權才能利用的漏洞，你可能要用不同的方式去評估優先順序。所以先看它是不是正在野外被利用，接著看 EPSS 分數，這也是關於已知漏洞與利用手法的指標，這些都是免費的資源，對吧？最後才用 CVSS 分數當作平手時的判斷依據。我會說，這是一個更有效的方式，能幫你把重要的修補程式排出優先順序，尤其是當你的時間窗已經沒有原本那麼寬裕的時候。
