**Megan Morrone：** 所以我想從開放這個主題開始談。最近有兩大新聞主導了話題循環，一個是開源權重（open weight）與封閉模型之爭，各方陣營都在站隊，大多數人站在一邊，另一邊主要是 Anthropic。不過這件事很複雜，真的很複雜。

**Megan Morrone：** 另一個新聞，我們等下也會談到，就是前沿模型在測試中失控、入侵了第三方網站。我想先從開放這個辯論開始，畢竟現場其實沒有真正站在封閉那一邊的人，所以我可能得扮演一下反方角色。我認為開源權重的論點常常會歸結到「安全 vs. 開放」：如果我們開放，就不可能安全。那我們先請 Matt 說說看。當有人說「開源權重模型本質上就是危險的」，你怎麼想？

**Matt White：** 這個論點我們以前也聽過，當年 Linus Torvalds 開發 Linux 的時候，也有人說開源是「魔鬼的傑作」，當時 Steve Ballmer 就講過類似的說法。

密碼學那時候也聽過同樣的說法，對吧？大家說密碼學會讓罪犯為非作歹。但大多數技術都是雙重用途的，AI 也不例外。我認為可以這樣論證：如果你在打造前沿模型，而那個模型具備可能對社會造成負面衝擊的能力，那麼實驗室確實需要思考該不該把它釋出。但歸根究柢，在前沿層級，尤其談到資安時，重點在於每個人都應該有能力保衛自己的基礎設施，每個人都應該有能力修補自己的系統。如果這件事是集中管控的，那用不了多久，某個地方就會冒出一個具備同樣能力的開源模型，到時候攻擊者反而會佔盡優勢。

所以我認為，就安全性而言，開放其實是在拉平競爭環境。

**Megan Morrone：** Mazin，我們剛才在後台聊到，你的基金會其實同時涵蓋開放與封閉兩邊，能不能談談你怎麼看開放與封閉的未來？

**Mazin Gilbert：** 好，首先，我們基金會裡的成員，從 Anthropic、OpenAI 這類公司到其他人，開放模型跟封閉模型都有人在做。所以第一點，不管是開放還是封閉，每一家打造模型的公司都有責任確保自己跑過基準測試（benchmark）、做過各種測試，並確保這些模型基本上是安全可用的。而且他們必須對這些測試保持透明，說清楚跑了哪些測試，這些模型對其他人來說到底有多安全。

但目前這種透明度還不完全存在，這是我們身為一個生態系需要繼續推動、並標準化的地方，讓它成為每一家模型供應商的常規做法。不過整體來說，就跟所有開放的事物一樣，不管是模型還是程式碼都沒有差別：一旦開放，就代表每個人都能取用，每個人都能嘗試、測試、修改、改進它。這跟封閉完全不同，封閉的情況下，只有少數躲在門後的人真正能接觸到核心，而你能拿到的只是一組 API。所以整體而言，我們看到開放反而更安全，因為它對所有人開放，有足夠多的貢獻者在檢視它。

Unix 就是這樣，Unix 是開放的；Kubernetes 也是這樣，Kubernetes 是開放的；PyTorch，Matt 也參與過，PyTorch 是開放的。所以你去看歷史上很多重大的技術革命，其實都是因為它們是開放的才發生的。

**Megan Morrone：** 難道事情就這麼簡單：OpenAI 跟 Anthropic 要準備 IPO，需要籌錢，所以就守住自己的秘密？就這麼簡單嗎？

**Ivan Burazin：** 我不確定。反過來說，就算美國這樣做，世界上其他地方還是存在。那對世界其他地方來說又代表什麼？如果我們在美國把這件事禁掉、列為非法，還是等於把能力留給世界上其他人拿去做壞事。

然後又回到那個論點：Hugging Face 和 OpenAI 發生的事情就是這樣——你反而無法保護自己，因為你手上從他們那邊拿到的模型不允許你自我防禦。這樣其實處境更糟，對吧？所以說，各種說法背後，其實都跟講這些說法的人本身的動機有關。當然，我們這裡有些人確實有很強的動機去說開放是好的，因為我們自己就有金錢上的誘因。但就算撇開這點不談，你仔細去看，也沒辦法讓全世界都把它列為非法，這代表美國自己反而處在比較不利的防禦位置，我認為這樣做並不好。

**Megan Morrone：** 那我們該怎麼走出這個局面？

**Ivan Burazin：** 我不認為我們能走出這個局面。我覺得這是個持續進行式，現在什麼事情都被極化、都被政治化，每個人都有自己的兩種立場，這種狀態會一直持續下去。但我很願意相信，封閉原始碼會繼續存在，前沿模型也會繼續發展，但開源同樣會存在，而且它能讓大家做很多事，就像你說的雙重用途一樣，你沒辦法阻止它同時被用在好的跟壞的地方，事實就是如此。所以身為一個社會，或者身為企業，我們現在必須從內部保護自己。你必須在內部做好防護，確保你的模型不會在內部或對外做出惡意的壞事。

同時你也必須對外防禦，抵擋其他惡意行為者。我的類比是：就像三年前，或者五年前的銀行，你仍然得防範內部員工做出惡意行為，也得防範外部真的有人來搶銀行的錢。從資安角度來看，每一家企業面對模型時，都得做這兩件事。

**Matt White：** 我想補充一點：我非常支持開放，但這不代表我反對封閉。是啊，我認為這兩種方案在市場上都有各自的位置，讓消費者自己決定要用哪一種。但競爭有助於把價格壓在合理範圍內，畢竟我可不想每百萬輸出 token 就花掉 300 美元，對吧？

開源模型有助於壓低那兩大主要封閉實驗室的價格。而且很明顯，就像你說的，使用這些開源模型還有很多好處，它們不會拒絕執行某些特定任務，對吧？當然，這也代表它們可能會做出一些不太理想的事情。但這時候，任何架設這些模型的人，都有責任建立自己的護欄（guardrails），確保安全，這個責任不見得落在推論服務供應商身上，而是說如果你是把服務提供給企業客戶或下游的使用者，你自己就必須建立好護欄。並不是所有東西都得內建在模型參數裡才行。

你有很多很棒的工具，像是分類器（classifier）、存取控制清單（ACL）之類的東西，可以整合進你的網路架構，你也可以改善你的 harness（代理程式的執行框架）跟其他相關環節。所以我認為說到底，還是消費者自己會決定要用什麼。我不認為「開源模型本質上不安全」這種說法真的符合大眾的普遍認知，但它確實對某些人的利益有幫助。

**Megan Morrone：** Dima，跟我們聊聊護欄這件事，這算是你們做的一部分嗎？

**Dima Dmytro Dzhulgakov：** 對，我認為說到護欄，重點其實更應該放在應用層，而不是核心技術本身。特別是在資安領域，我覺得這真的是雙重用途，而且也很難定義到底什麼才是「正確的護欄」。

對吧？我們實際上有拿封閉原始碼跟開源模型，在各種資安基準測試上跑過。有趣的是，目前的開源模型在這方面表現反而比前沿模型好很多，因為前沿模型常常直接拒絕執行這些基準測試。就算提示裡已經明確寫清楚：「嘿，我在修補自己的程式碼庫，我想找出漏洞」等等，它還是拒絕，這其實跟 Hugging Face、OpenAI 那件事的經驗很類似。所以我認為，特別是在資安領域，要在通用模型的 API 層級找到精確的決策邊界真的很困難。我覺得更重要的是把力氣放在推動監管等等的方向，因為對於潛在危險的產品，還有其他瓶頸可以把關。

尤其是當你更深入實體世界的時候，才能真正落實安全性、建立更好的護欄。我認為資安領域在歷史上一直很難處理，因為攻擊跟防禦看起來太相似了。從過去密碼學的監管經驗，或是 Linux 之類的例子中，我們學到的是，真正確保環境安全的最好方法，其實是讓更廣大的社群有能力自我防禦，這才是防止攻擊者得逞的最佳方式，而不是去限制技術本身。至於其他有潛在危險的領域，我認為實體世界的瓶頸比較多，用限制的方式可能還比較實際一點。

**Ivan Burazin：** 我可以就這點問個問題嗎？

對，我只是好奇，不是要讓你難堪。我只是好奇責任歸屬這一塊：我猜封閉原始碼那邊之所以有很多事不能做，是因為他們如果出了問題，在法律上有可能要負責，對吧？那如果我自己後訓練（post-train）一個模型然後自己跑，出問題我就自己負責。但如果是你們幫忙跑模型的話，你們會不會擔心這件事，會不會因此在上面加裝護欄？還是說責任其實在打造這個模型的人身上？

**Dima Dmytro Dzhulgakov：** 我認為根本上要看的是，最終是誰在使用這個應用，這才是真正要負責的對象。拿你的類比來說，如果你是 AWS，然後有人在上面跑惡意程式碼，如果規模夠大，他們就會跟政府、監管單位合作處理等等。

對對對，當然他們會把它關掉之類的。但 AWS 不可能去稽核你上傳的每一個 Docker 容器，看裡面有沒有惡意程式碼。我認為對基礎設施供應商來說，這才是合理的做法。監管這件事沒辦法脫離具體應用層面單獨進行。

**Megan Morrone：** Matt，你剛才說你支持開放但不反對封閉，這是不是有點像 Anthropic 的 Dario 這禮拜說的話，他說他支持封閉但不反對開放？雖然不完全一樣，但算是相反、對偶的說法。所以我很好奇，這是不是我們這些記者小題大做了？還是說在業界裡，這真的是大家實際擔心會發生的事？

**Matt White：** 我覺得敘事已經變了，對吧？兩週前的說法是「封閉本質上就不安全」，現在變成「我們正處在前沿，前沿本身就不安全」，所以照這個邏輯，開放的東西也不安全，封閉的東西也不安全。但至少封閉的話，我們可以當個負責任的守護者，保護這個世界，對吧？敘事雖然變了，但底層訊息其實一直沒變，就是「開放本質上不安全」。這其實是個很老掉牙的說法了，根本沒有事實根據。我認為唯一值得考慮的地方——我知道很多研究人員也在想這件事——是如果模型觸及某種前沿級的能力，可能會讓整個世界或整個基礎設施陷入危機，這種情況確實需要特別考量。

我認為這正是現在很多人開始在談的事。Demis 之前有提議過，成立某種組織來判定一個模型是不是達到前沿級，以及是否需要被限制發布，對吧？我不確定這樣的監管最後會變得多嚴格，但可以肯定的是，所有實驗室都有責任當個負責任的守護者，自己判斷該不該把東西釋出。但我可以跟你保證，美國這邊做的安全測試相當嚴謹，會花不少時間，也因此拖延了模型上線的時程，但確實做得很嚴謹。中國那邊就沒有同樣的嚴謹程度，模型後訓練一完成，基本上就準備出貨了。

這就牽涉到競爭之類的問題，是不是為了競爭而犧牲了安全性。我不確定每個國家在「當個負責任的模型發布守護者」這件事上，會不會有一致的共識。

**Mazin Gilbert：** 補充一點，不管是開放還是封閉，我們過去一個月經歷的這些漏洞事件，其實跟模型本身沒有關係，好嗎？這種事開源模型也可能發生，而事實上是發生在封閉模型身上。我覺得這只是說明這些模型越來越聰明了，這點無庸置疑，不管開放還是封閉都一樣。問題出在模型周邊的東西：代理程式應用、還有 harness（執行框架）。

是圍堵機制（containment）得跟上這種複雜程度的問題。所以我認為不管最後結果如何，開放跟封閉都會有各自的空間。我們打造應用程式並交付給客戶時，仍然要負起責任，不管用的是哪一種模型，都得確保有圍堵層、確保有護欄、確保關鍵決策有人在迴圈中（human in the loop）、確保有閘道（gateway）存在。我們不確定 Anthropic……當時 Anthropic 到底有沒有用閘道？因為通常如果你有用閘道，就不會讓代理程式在沒有閘道的情況下直接跟外部世界對話。

**Matt White：** 我記得他們說的是……所以這裡面有很多環節……對，OpenAI 那邊有個代理伺服器（proxy），裡面有個零時差漏洞（day zero exploit），對吧？

不過這點提到 harness 講得很好。真正在驅動這件事的不只是模型本身，harness 同樣扮演很重要的角色。我有個理論，覺得有些新模型的訓練資料，其實刻意包含了尋找系統漏洞的軌跡，藉此讓它們具備這種能力。所以這並不只是一種湧現特性（emergent property），而是實際上就是 RL 訓練過程的一部分。

**Dima Dmytro Dzhulgakov：** 沒錯。不過我想補充一點，有件事挺有意思，就是它並沒有發生——照理說你應該可以用同一組代理程式或 harness，先拿它去測試看看有沒有零時差漏洞，再讓它去執行可能利用那個零時差漏洞的任務，對吧？

你其實也可以這樣做，先找出漏洞在哪。

**Matt White：** 對，說到 harness 跟監控這點，你也可以派一個能力相近的模型，去執行監控軌跡、觀察發生什麼事這樣的任務。

**Dima Dmytro Dzhulgakov：** 對，這是完全可觀察的，我們需要的其實就是打造安全系統的最佳實務。

**Matt White：** 我同意。我覺得再過兩三個禮拜，我們就不會再談開放跟封閉權重這個話題了，我們會開始討論 harness。這個領域發展真的太快了，每天都有新東西冒出來。
