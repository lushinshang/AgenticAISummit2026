系統擁有控制力，而這裡有個持續存在的挑戰，就是「控制力不足」。歸根究底，問題出在主要的控制介面——也就是提示詞——本身缺乏任何精確的語意。我這麼說是什麼意思？想像你有一個銀行業務代理人，使用者可能會上前來要求貸款，而在代理人的另一端，則是一堆金融 API。這個代理人也會有一些指令，其中有些指令本質上是「軟性」的，像是「要讓人感到安心」；但有些指令本質上是「硬性」的，像是「報價只能透過這個 API 授權」之類的規則。問題在於，一旦你把指令放進提示詞裡，它們就全部變成軟性的了，你放進去的字詞跟你得到的行為之間，沒有任何真正明確、清楚的關係，這是個真實存在的挑戰。那大家都怎麼做？我想這個房間裡很多人都有過這種經驗：把提示詞重新措辭、把某些內容全部改成大寫字母、在指令最後加上幾個驚嘆號，也許加到第三個驚嘆號的時候，你就開始覺得，這根本不是硬性控制該用的正確控制介面。那大家實際上都在做什麼？我們可以用其他類型的控制結構，舉例來說，你可以試著透過外部的「框架」(harness)來取得硬性控制，讓模型去檢查模型，或用程式碼去驗證結果，這算是往前邁進了一步，因為現在你至少有辦法做到某種硬性

控制，但這仍然非常有挑戰性，因為讓模型去檢查模型，會增加延遲、增加成本，而且維護起來可能是一種相當複雜、不可靠的架構。我們真正想要的，是模型本身一開始就內建針對硬性限制的控制介面，並且在模型內部就完成驗證，這正是我們在 Scaled Cognition 採取的方法，我稍後會多談一點我們的模型。我認為這將會愈來愈成為大家看到的方向。好，以上談的是輸入端的架構，也就是你怎麼控制模型；但我們也需要談談來自輸出端架構的障礙。我們希望模型能說真話，最好是能以某種可驗證的方式保證它說的是真話，但「可驗證的真話」跟「碰巧輸出一串正確的詞元」之間，有很大的差別。舉個例子，如果我問一個模型柏克萊的人口是多少，它會拼湊出一些詞元來回答我。也許它拼湊出來的是這些詞元，聽起來合理，但其實不對；也可能它拼湊出來的是這些詞元，一樣聽起來合理，而且剛好是對的。這不代表模型答對的次數不會比答錯多，希望大部分時候它都是對的，但重要的

是，一個原生的大型語言模型其實沒辦法真正分辨，自己是「知道」還是「不知道」，這些都只是猜測，有些猜對了，有些猜錯了。那要怎麼樣才能真正有把握？這需要某種「後設認知」的能力。你可以在某些系統裡看到這種能力的雛形，舉例來說，一個系統會發出查詢去呼叫工具或呼叫 RAG 系統，它自己決定要執行這個查詢，再輸出結果，這其實已經開始走向後設認知了，也就是對「你將如何進行運算、如何思考」這件事本身進行運算。這不是後設認知唯一的形式，舉例來說，如果我問在座各位柏克萊的人口是多少，大概最常見的答案會是「我不知道」，人類非常擅長追蹤自己是否掌握某項知識，但現在的系統做不到這一點，而我認為系統具備後設認知的能力，將會愈來愈重要。好，當然，一個系統的行為，跟它是怎麼被訓練出來的息息相關。系統的行為現在愈來愈多不只來自預訓練，還來自後訓練，而後訓練通常是以強化學習的方式進行。大家應該都聽過很多基於強化學習的驚人進展，像是在數學或程式撰寫這類領域，曾經出現過爆發性的進步，這是因為這些是可驗證的

領域，就像遊戲一樣。在這些領域裡，你可以先用 Lean 這類工具驗證你的證明，再拿去訓練模型，或是直接交給使用者作為輸出。所以可驗證的強化學習可以非常、非常強大，但大多數領域其實並不是可驗證的。不可驗證的強化學習會怎麼造成問題？它可能會以犧牲智慧其他面向為代價，去提升某些面向。讓我用一個「物流機器人」的寓言來說明：有個使用者跑來問物流機器人：「我的訂單在哪裡？追蹤資訊已經好一陣子沒更新了。」物流機器人查了資料庫，發現包裹弄丟了，於是它說：「你的包裹弄丟了。」到目前為止都還好，但如果我們在這上面疊加強化學習，而且做得不小心，會發生什麼事？也許我們告訴系統要最佳化「按讚率」，可能是以淨推薦分數之類的形式呈現，那這個答案大概不會得到按讚，但如果它說「你的包裹正在路上」，使用者可能至少短期內會比較開心。這下你等於是在教你的系統對你說謊，而這種事情真的會發生嗎？確實會，舉例來說，如果你用 RLHF，它可能會提升人類對輸出結果的認可度，同時實際上卻降低了輸出的事實準確性。好，最後但同樣重要的是，打造可靠系統的其中一個障礙，是「超級智慧其實非常昂貴」。我們其實已經知道原因了，舉例來說，你可能是在為你根本

不需要、也不想要的廣度買單；你可能是在為模型互相檢查而付出代價，不管是以詞元數量還是延遲時間來計算；或者你可能是在為「測試時計算」買單，這本質上就是在測試當下教模型做一件你其實希望它事先就已經學會的事。這些全部都可能花費很高的成本，結果就是你會在通用型模型上看到這種取捨：這裡你可以看到一堆模型放在一個代理人基準測試上，左上角的模型準確但昂貴，右下角的模型比較不準確，但成本效益高得多。那要怎麼跳脫這條曲線？舉例來說，我們的模型 APT，是一個專門針對代理人互動打造的模型，意思是一邊面對人類，另一邊面對 API，這是一個專用、能自我驗證的模型，這讓你能同時取得高準確度和高效率，我認為這將會愈來愈成為解決方案的一部分。
