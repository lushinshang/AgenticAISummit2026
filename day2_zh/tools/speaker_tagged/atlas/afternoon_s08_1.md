**Aravind Segu：** 很好，很好。目前市面上有一大堆 harness，大家都在用。但問題是，要操作它們、採用它們非常困難。我們在 Databricks 就親身體驗過這一點。我們有超過 3,000 名工程師，各自使用不同的 AI 工具，我們發現要打造一個統一的生態系非常困難。採用代理人（agent）很容易，但要操作它們卻不容易。我們看到的一些問題是：首先，這個領域非常擁擠。市面上有非常多 harness，而且每週都有新的 harness 冒出來，要跟上所有正在發生的事情非常困難。

我們在 Databricks 親身經歷過這一切。大家以前會透過 Slack 訊息互相傳送 Claude MD 檔案，好讓對方了解，喔，我的代理人做了這件事，你可以把你的代理人加進來，請它去做別的事嗎？我們會設定私有的工作樹（work tree），在裡面提交虛擬程式碼（pseudocode），這樣我們才能一起協作、共用一些工作階段。每次我們想要開始使用 Codex，就得重新設定所有的 MCP 伺服器，確保一切都能上線，並且能跟我們內部系統正常運作。就在那個時候，我們意識到我們需要的是一個新的層級，一個位於 harness 層級之上的開放新層，這就是我們所謂的「中繼框架（meta harness）」。於是我們著手打造這個中繼框架，也就是我們建出來的 Omnigent。

它是給 AI 代理人用的中繼框架。Omnigent 是完全開放原始碼的專案，你現在就可以貢獻程式碼、可以直接試用，它提供你一個代理人式（agentic）的開發環境。你可以在桌機、行動裝置，或任何其他平台上使用它，而且它讓你能夠在背後透過你既有的設定去使用任何 harness，大大提升你的使用體驗。至於 Omnigent 實際運作的一些技術細節，這裡的 Drew 會帶大家看一些投影片。好，我就交給他了。

**與談人 B：** 好，謝謝你，Erwin。這就是 Omnigent 背後的「為什麼」。接下來讓我告訴大家 Omnigent 到底是什麼。這裡的模型刻意設計得相當簡單。

它分成兩個部分。一個是伺服器（server），這是你的工作階段（session）所在的地方。你所有的工作階段歷史紀錄、政策、MCP 伺服器、技能，全都放在同一個地方。你的自訂代理人也存放在這裡。另一方面，我們有一個執行器（runner），這是代理人實際進行工作的地方。這可以是你的筆電、某種開發機（dev box）、Kubernetes pod，或是某種雲端沙箱（cloud sandbox）。而在這兩者之間，是一組共通的 API。每一個介面都使用這組 API。所以終端機、網頁使用者介面、原生桌面應用程式，全都使用同一組 API。也正因為如此，因為伺服器位於這一切的中間，一個工作階段就不再被困在單一機器上的單一終端機裡。

所以你可以闔上筆電，這個代理人仍然會繼續運作。你可以從手機上接續這個工作階段。這個架構上的選擇為我們帶來了幾個好處。第一，我們得到了組合性（composition）。每個 harness 都接入同一層，所以你可以跨 harness、跨模型組合代理人，或是在專案進行到一半時切換 harness，而不需要重寫任何東西。第二，你得到了協作（collaboration）。工作階段存放在伺服器上，所以是可以分享的。你可以把一位隊友帶進一個正在進行中的工作階段，讓他觀看、操控，或是針對你代理人正在產出的檔案與其他成果物（artifact）留言。就像 Arvind 提到的，再也不用把終端機截圖然後用 markdown 格式傳出去了。第三，我們也得到了控管（control）。

因為伺服器能看到整個工作階段，它能看到每一個提示（prompt）、每一次工具呼叫、每一個被動過的檔案，這讓我們能夠針對安全性與成本打造真正聰明的政策，同時也有強大的作業系統層級沙箱（OS sandbox）。讓我針對每一項再深入說明一下。開箱即用，Omnigent 就能與超過十幾種 harness 溝通，包括 Cloud Code、Codex，我就不在這裡把整份清單念出來了。這裡有三件重要的事。第一，完全不需要遷移（migration）。Omnigent 會直接沿用你機器上既有的設定。所以如果你已經設定好訂閱、MCP 伺服器、技能，這些都會直接帶進來，在 Omnigent 裡馬上可以用。

第二是跨 harness 的編排（orchestration）。如果明天 Cloud Code 多了一個 Codex 沒有的功能，你不需要另外開一個終端機、把你的脈絡（context）複製過去。你可以直接在同一個工作階段裡要求使用它。可以讓一個模型負責實作程式碼，讓另一個模型負責審查。第三，它非常具有擴充性（extensible）。我們有一套 harness 外掛（plug-in）SDK 系統，讓任何人都可以在不動到 Omnigent 核心套件的情況下，發布自己的整合。舉例來說，Atlassian 有一群人打造了他們自己的自訂 harness，叫做 Robo，他們完全不需要動到 Omnigent 本身，就把它整合進 Omnigent 了。而因為不同的 harness 各有所長，這件事就變得非常強大。

在 harness 之上，你也可以定義自訂代理人。一個代理人在 Omnigent 裡其實就是一個 YAML 檔案，裡面包含系統提示（system prompt）、一個模型，以及一些你想給它的工具。有趣的地方在於，你也可以開始加入其他代理人的工具，而這些其他代理人可以是建構在不同 harness 之上的。我們在 Omnigent 裡附上了幾個範例，我最喜歡的一個叫做 Poly，我們等一下會實際示範。Poly 是一個多代理人程式碼編排器（multi-agent coding orchestrator），它可以把任務並行分派（fan out）到不同的 harness 上。所以你可以讓 Cloud Code、Codex、Cursor，以及任何你想要的其他 harness，同時並行地實作與審查你所有的程式碼。而且因為代理人在 Omnigent 裡也只是單純的 YAML，所以它們非常方便攜帶（portable）。

你可以把你的代理人分享給團隊，或是把它們發布到整台伺服器上，而且同樣的政策與沙箱機制會套用到所有的自訂代理人上。接下來是控管（control）。大多數工具裡的政策，都是單獨檢視一個動作：這個指令允許還是不允許？是或不是？在 Omnigent 裡，政策看到的是整個工作階段，它們能同時看到傳入的資料、正在請求的動作，把這些全部一起考量進去。而且執行的細緻度非常高，你可以設定一項政策為允許、拒絕，或是要求由人來核准。我們內建了一整套政策庫，而且政策本身就是用 Python 定義的，所以你可以非常輕鬆地新增自己的政策。舉例來說，Red Hat 有幾位同仁開發了一些政策，用來偵測他們的代理人何時卡進迴圈，然後把那些代理人停下來。

而監控安全性的同一套機制，也同時監控你的成本。今天我想談的內建成本功能主要有兩個。第一個是預算（budget）。我們大多數人對於 AI 的使用都有某種每月或每週的預算。但在工作階段進行到一半時，你其實不太清楚自己目前花了多少錢，燒掉了多少錢。所以預算政策提供你一些軟性檢查點（soft checkpoint）。假設你的上限是 100 美元，花到 20 美元的時候，它會跳出提示告訴你：嘿，你已經花了 20 美元，要繼續嗎？我喜歡的地方在於，這不是一個硬性上限，或者你也可以設定成不是硬性上限。你可以把它設定成一個降級閘門（downgrade gate）──如果我在前沿模型（frontier model）上已經花了 20 美元，也許就開始降級改用更划算、更便宜、更小型的開源模型。

也有以每個工作階段為單位的版本，以及以每位使用者每天為單位的上限，你可以透過政策在整台伺服器層級強制執行。第二，我們也有智慧路由（smart routing）。我自己完全是那種即使是最小的任務，也會選用最大模型、最高努力等級（effort level）的人。而現在 Omnigent 有一個更好的選項。透過「auto」選項，我們有一個輕量的分類器，會檢視任務內容，替你挑選 harness 與模型。如果是個大型設計任務，我們可以挑選前沿模型；如果是個小修正或簡單問題，我們可以挑選又快又便宜的模型。接下來是協作（collaboration）。這是我個人在 Omnigent 裡最常用的功能。任何工作階段都可以分享，可以是唯讀模式，也可以是完整編輯模式。

而且別人可以跟你一起共同操作（co-drive）你的工作階段。這個我們稍後也會示範。我們經常看到的模式，其實很像 on-call 值班的情境：有人花了整整一個小時，跟代理人一起針對某個問題建立脈絡，然後遇到卡關的地方，一個需要找隊友幫忙的卡點。這時候你不需要把歷史紀錄或最後的 cloud 回應複製貼到 Slack 裡，而是可以直接把隊友拉進這個工作階段，讓他們接手操作你的工作階段，而所有的脈絡都已經在那裡了。而且，你還可以針對所有已產出的成果物留言，幾乎就像 Google 文件的編輯風格，但用在代理人式的工作上。你可以在程式碼、markdown、HTML，以及 PDF 上留言。

一旦這些留言累積起來，你只要按下介面上的「全部處理（address all）」按鈕，它們就會被注入一個提示，送給你的代理人。到目前為止我展示的一切，都可以在你想要的任何地方執行。在雲端這一側，Omnigent 透過單一介面連接許多沙箱供應商。我們支援 modal、Daytona、E2B，以及一般的 Kubernetes。我們也有 Databricks 沙箱，可以在你的 Databricks 工作區裡執行代理人。雲端沙箱正是讓你能夠「永遠在線」的關鍵：你可以從筆電啟動一個工作階段，然後闔上筆電，之後不管你人在哪裡，都可以從手機上接續查看。而所有這些供應商同樣也是外掛。所以如果你有一套適合自己的開發機（dev box）設定，你也可以在 Omnigent 裡替它打造一個外掛。

而且可以很輕鬆、幾乎不費力地把這套開發機設定帶進 Omnigent，也不需要經過我們任何人的 PR 審查。為了做到縱深防禦（defense in depth），我們還有 Omnibox，這是我們內建的作業系統層級沙箱。它會在作業系統層級把代理人限制住，原生支援 Linux、Mac OS 與 Windows。我們會在代理層（proxy）注入憑證，所以你的代理人永遠不會看到你真正的憑證或原始機密資訊（secret）。這在雲端沙箱裡同樣適用。所以即使你使用像 Daytona 或 modal 這樣的雲端沙箱，你也已經內建了作業系統層級的沙箱。所以爆炸半徑（blast radius）永遠很小。這就是我們的想法：AI 需要一個位於 harness 之上的層級。harness 生態系每個月都會持續產出很棒的工具。
