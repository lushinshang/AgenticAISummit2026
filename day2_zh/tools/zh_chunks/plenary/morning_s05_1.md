其實在我來柏克萊之前，我做了好幾輪博士後研究，前前後後住過大概九個不同的國家，去過九所大學，在世界各地不同的地方生活過。我覺得柏克萊，尤其是加州大學柏克萊分校，非常特別。柏克萊特別的地方在於，這裡有一種你可以質疑一切、可以改變一切的態度。當然，整個學術界某種程度上都有這種精神，但柏克萊特別強烈。我記得剛加入研究小組時，其實有點文化衝擊，因為我們在做的那些東西，我心想，這不算研究吧，我們不應該這樣做啊。

大家就說，不，我們就是要這樣做，這很酷，這會有影響力。我當時想，這說不通啊，這很怪，你們這是在投機取巧吧。結果大家說，不，我們什麼都可以做，我們就是來改變世界的。所以我覺得那就是柏克萊的精神。這所大學有這種精神，這座城市也有，這是它的歷史，我想這就是讓它特別的原因。有時候這種精神會走得有點極端。有些研究影響力極高，但也有一些研究方向走得很遠。我記得有個研究是關於「延遲容忍網路」（delay tolerant networks）。

當時的想法是，現有的網際網路對星際通訊來說根本不夠用，所以我們得為星際通訊重新設計一套新的網際網路，因為總有一天人類會殖民整個宇宙。那是這裡網路研究小組的其中一個研究計畫。所以我覺得柏克萊的視野真的非常寬廣，這也幫助大家把眼界打開。對，我記得早期我們是作業系統與分散式系統研究小組，深受 BSD 啟發。我記得後來成為 Mesos 的那個專案，名字經過好幾輪迭代。我提出的其中一個候選名稱是 Berkeley Cloud Distribution（柏克萊雲端發行版，BCD），或 Berkeley Cluster Distribution（柏克萊叢集發行版），靈感來自 BSD，Berkeley Systems。

還有 BDAS，柏克萊某某發行版。不不不，是有個 BDAS，發音就是「badass」。對，badass，這是官方的命名方式，你得把它念成 badass，也就是 the badass stack。但不，這是我當初為 Mesos 提出的名字，我說我們應該叫它 BCD。對。我不知道你還記不記得，我很確定 Matei 和 Ben 兩個都說，不行不行不行，我們有什麼資格這麼自大，取一個跟 BSD 只差一個編輯距離的名字。我當時想，好吧，那我們就靠自己做出一個更有影響力的作業系統來證明自己。所以，沒錯，我那次投票沒贏。我覺得 Mesos 這個名字其實蠻好的。對，這就是那種生日般的精神。對。

質疑既有規範，這個精神一直延續到 Databricks。我們最近宣布——其實我們每週都會宣布很多東西——Omnigent 就是一個很大的開源框架，試圖在 harness（代理執行框架）這個層面上發揮作用，也可以說它是為 harness 提出了一種新型路由器。我們也談到 open evals（開放評測），這個之後可以再多聊。以你身為 Databricks 領導者這麼多年的角度來看，我們從柏克萊帶出來的那種開放創新、天空才是極限的心態，是怎麼延續到 Databricks 的策略裡的？嗯，我認為開放這件事對我們來說一直非常重要。我們一向希望推動開源標準、開源介面，因為這會催生社群。

而這些社群會變得非常有力量。事實上，如果沒有 Spark 生態系，Databricks 這家公司根本不可能存在，因為 Spark 生態系遠比我們任何一個人能做出來的東西都要龐大得多。所以這對社群有好處，對世界也有好處，同時也證明了這是一個好的商業模式，Databricks 本身就是證明。所以我們持續這麼做，並且會把心力放在我們認為最有用、影響力最大的地方。幾年前，我們做了 MLflow。很多人不知道，MLflow 現在每個月仍有四千萬次下載，也就是說每年有數十億次下載。那是什麼樣的背景？那大概是機器學習時代，也就是十年前左右，大家都很執著於找出最好的模型，但機器學習從業者要在不同模型之間反覆迭代其實非常困難。

他們需要一種類似 Git 版本控制的東西，能夠迭代並追蹤所有不同的實驗紀錄，這就是 MLflow 的由來。你剛提到的 Omnigent，則是源自於市面上出現了太多不同的 harness。而且和大型語言模型不一樣的是——大型語言模型的話，大家會很快在不同模型之間切換，因為它們本質上是隨機的，你每次問同一個問題，得到的答案都不一樣。我們從 Databricks 的資料裡就能看到這一點，因為我們同時服務各種不同的模型，包括專有模型和開源模型，所以我們手上有這方面完整的資料。我們看到大家在不同模型之間切換得非常快，只要一有新的專有模型或開源模型推出，短短幾天內大家就會轉移過去。

我們從沒見過這種現象。軟體世界的其他東西通常都有黏著度，你會一直用下去，慢慢地才會出現衰退，使用者會緩慢流失、遷移，但這需要一段時間，不會瞬間發生，不會大家一夕之間全部倒戈。但大型語言模型就是會這樣。不過我們也發現，大家開始在這些模型之上搭建 harness，而這些 harness 反而變得像舊式軟體一樣，會把你鎖住，你會習慣它的介面、記憶功能、快捷鍵之類的東西。所以我們想做一個東西，讓大家可以真正在這些 harness 之間自由切換，而且完全開放。這個構想就是「元 harness」，也就是 harness 的 harness。它可以搭配你的 Claude Code 使用，也可以搭配 Codex，其實可以搭配任何一種，OpenCode、Pi，隨便你說得出名字的都可以。

這樣一來，你就能同時享有多工切換的彈性，也能享有社群的力量。這個專案我們是今年夏天才剛推出的，我記得才短短兩週，GitHub 上就有一千個 fork，真的是一炮而紅。而且短短幾週內就有數百人立刻投入貢獻。所以我們非常興奮，我認為我們會持續推出這類開源專案。我認為接下來這幾年，開源其實會迎來一波巨大的紅利，多虧了 Vibe Coding 或者說 AI，因為以前像 Linus Torvalds 要打造一整套作業系統，跟 Windows 這種對手競爭，需要投入極大量的心力，到最後總得有人付他薪水，所以他才會被公司雇用等等。

但現在，因為寫軟體的成本正在下降，我認為這件事會變得容易接受許多，我們會看到更多、更多的開源專案冒出來，並且成為業界標準。我有一個理論，跟這個不完全相關，但我感覺我們會走向一種新版本的 GitHub，屆時 pull request 裡裝的不再是程式碼，而是提示詞（prompt）。然後審查者要做的，就是去執行那些提示詞。我覺得我們正朝這個方向前進，像是在 OpenClaw，也許 Spark 也是，維護者現在要做的工作，更多是判斷這段程式碼有多少比例是人類寫的，或者說，一個人到底在這個 pull request 上花了多少小時。

我不知道，這讓我開始思考，你我成長的那個世界，還有我們創辦 Databricks 時的那個世界，未來會發生多麼根本性的改變。你對 Databricks 面對的這種典範轉移，或者說軟體開發與 Vibe Coding 的未來，有什麼看法嗎？嗯，我確實認為我們正越來越走向這樣的方向：只要你能清楚定義程式該做什麼，並且有測試的基礎和 harness 支撐，那具體怎麼實作其實已經不重要了。AI 可以自己找出最快、最好的實作方式，你可能得一次又一次地重寫它。但這真的需要你有一套非常嚴謹、滴水不漏的方式來定義規格（spec）。

我覺得我們正往這個方向走。對，這讓我想到評測（evals）的事。我們 Databricks 最近宣布了一項內部作業，我們把自己內部大量的程式問題與工作任務蒐集起來，建立了一個資料集，一個非常龐大的資料集。有多少筆？超過一千筆？對，是一個很龐大的資料集，因為我們大概有四千名工程師每天都在寫程式碼。而整間公司大約有一萬一千人，每天都在提出各種問題，像是資料科學相關的問題，他們想知道業務狀況如何，因為他們就在第一線工作。我們把這些全部蒐集起來，這基本上就是一份宣告式規格（declarative spec）。對，就像你把這些問答都宣告式地寫進去，我猜是這樣。對，就是有人提出問題，然後你有對應的 Databricks 標準答案。

現在你就有了一份規格，讓 agent 可以照著學習、去回答這些問題，就像是說，這裡有一堆問題，我們希望我們的 agent 能夠回答出來。這就成了一套針對 Databricks 量身打造的評測或基準測試。對。你覺得其他企業科技公司，或者更廣泛的企業，也在做這件事嗎？其實我對評測這件事有蠻多想法的。對，我們可以深入聊聊這個。嗯，我認為現在污染（contamination）的情況真的很嚴重，所以我們才想擁有一個屬於自己的「基準真相」（ground truth）。幾乎每天都有新模型發布，所以我們想要有一個屬於自己的基準真相，來判斷該用哪個模型，比方說，我們能不能直接用 GLM 5.2？它會一樣好嗎？

還是不會？諸如此類的問題，這就是我們想做的事。整體來說，前沿實驗室太過執著於「超級智慧」以及邁向超級智慧的進程，導致我們每天真正想做的很多事情，根本不在他們的評測範圍裡。他們專注在 HLE（Humanity's Last Exam，人類最後考試）上，HLE 裡有非常複雜的數學題和物理題。但當我們真正去看那些我們每天想做的基本任務時，模型的表現其實沒那麼好，最難的那批題目，正確率大概只有百分之四十——不對，是百分之二十，中等難度的題目大概百分之四十正確。而這些都只是很基本的問題，比如說，這裡有一份一九四〇年代美國的預算資料。

請你幫我們找出當時的國防支出是多少。這就需要掃描 PDF，並且搞懂當年的資料呈現方式，然後從中解讀出來。結果你會發現，這其實非常困難，因為大家的心力都放在物理和數學這種可以用強化學習（RL）訓練的題目上，而不是這種平凡的企業或商業任務上。所以我們想出了一個評測，我們叫它 Office QA，取自電影《Office》裡的 TPS report。我們想，好，就來解決這個問題吧，於是我們專注在這上面。有了這個評測之後，我們成功打造出一個 agent，能夠處理 PDF 解析之類的工作，正確率接近百分之八十。所以我認為，評測和規格未來會變得極其重要。

你自己也在 Terminal Bench 上推動了不少工作，那是由 Laude 發起的，對吧？對。我們和史丹佛的一位教授 Ludwig Schmidt 合作，他的團隊做過一些很有份量的工作，像是 CLIP，還有 DataComp 這類專案，在評測和資料領域都很有影響力。Ludwig 之前做的 DataComp，基本上是說：與其固定模型、改變資料集去看結果，不如反過來，固定模型和 agent，改變資料集，然後設立一個排行榜，看看改變資料集能不能讓同一個固定的 agent 表現變得更好。所以 Ludwig 在史丹佛的基準測試領域是個很重要的創新者，我在 NeurIPS 遇到他。

而且，就是在那場 NeurIPS 上，我們推出了一個叫 K-Prize 的東西，那是……K-Prize。對，K-Prize。對，當然，是我出的。我在台上直接說，我要開一張支票給你。我在 NeurIPS 台上發推文，承諾要開一張一百萬美元的支票，給第一個在我們稱為「無污染 SWE-bench」的測試上達到百分之九十正確率的團隊。做法基本上是，讓軟體工程師在一個測試集上寫他們的 agent 程式碼，這個測試集是我們新蒐集的 GitHub issue，我們說，這裡有一批來自 PyTorch 或 Spark 這類熱門專案的 issue，你的 agent 得負責修好它們。當然，如果測試集是公開的，agent 是有可能被拿去針對測試集訓練的。

所以你可以做兩件事：一是把測試集保密；二是承諾在所有參賽者都提交作品之前，都不去蒐集測試集內容。我們採取的是後者，我們定了一個截止日期，讓大家在這之前提交自己的 agent 程式碼，然後我們在那之後的四個月裡持續蒐集新的 GitHub issue，再拿這些新 issue 去對提交上來的 agent 做評測。結果大概是百分之十左右的成功率，對一個全新的基準測試來說，這已經算相當不錯了。從那次發布之後，再跟 Ludwig 聊到他……是不是很瘋狂，每個基準測試都會被刷到飽和百分之九十，但只要一推出新的，馬上又掉回百分之十。對，然後就這樣開始一個循環，這也是我們幾週前才剛宣布的新方向。

這就開啟了一個我認為非常沒效率的循環：每次都幾乎把上一版基準測試整套丟掉，從零開始重來。結果我們做了 Terminal Bench 1，接著是 2，再來是 2.1。從 2 到 2.1，我們主要是在修正五到十個題目，那些後來被發現根本無解的題目。但很多基準測試根本連這種小版號的更新都不會做，不會去修那些壞掉的題目。於是就形成了一種「地下文化」：真正熟悉 Terminal Bench 2 的人才知道，那個百分之八十三其實等於百分之百，因為裡面本來就有一些無解的題目。如果你是基準測試的製作者，你不會希望這樣，你會希望百分之百是可以達到的目標，只是很難而已。

所以我們做了 2.1，這也讓我們意識到，我們現在做基準測試的方式其實蠻蠢的，這就像在滾輪裡追逐名聲的倉鼠，做完 2.1 之後……我們是做了 2.1，雖然大家通常連小版號更新都不做，但接著你又要做 3，然後 Terminal Bench 3 就會是一整套全新的題目，跟 Terminal Bench 2 幾乎沒有重疊。我們認為應該反過來，把基準測試當成軟體來寫，也就是說，你不會每次做 Spark 新版本的時候就把整個程式碼庫丟掉重寫，你只會針對程式碼庫做修改，修修 bug；套用到基準測試上，就是把已經飽和的舊題目刪掉——既然現在大家都能答對了，那就不必再留在基準測試裡——然後加入十個更難的新題目。

這樣會健康得多，因為你可以每兩三週就發布一次新的基準測試版本……就像一直在更新一樣。對，就像軟體一樣。真的就像軟體。這樣講很合理。而且你也在修 bug。對。其實我很喜歡這個想法的一點是，這正好呼應了古哈特定律（Goodhart's Law）：任何你拿來評估某件事的指標，一旦被拿來當目標追逐，就會失去原本的意義，因為它會被鑽漏洞。所以這個做法剛好完美對應。對，沒錯，你要確保你的基準測試……因為這正是現在正在發生的事，這就是為什麼現在到處都是百分之九十。所以你也可以溫和地引導它的方向，因為隨著前沿技術演進，我們會發現，比如說現在，reward hacking（獎勵駭客）正變成前沿議題的重要一環。

一年前幾乎沒什麼人在談 reward hacking，現在很多人開始思考怎麼圍繞這個問題打造新的工具，agent 也越來越擅長辨識這種行為。我們希望有更多對 reward hacking 有抵抗力的題目，或是明確測試 agent 對 reward hacking 抵禦能力的題目。這種事我們一兩週內就能做到，想出三個新題目，發布一個新版基準測試。所以從 Terminal Bench 3 開始，之後會很快推出 3.1、3.2、3.3 這種相對小規模的漸進式更新。對這件事我蠻期待的。我確實相信基準測試正在發生劇烈的變化，我也深信你剛才說的：只要你有好的評測，agent 和 harness 的程式碼會越來越自動地被最佳化。

這跟早期像 LangChain 或 LangGraph 這類框架有很大的不同，那時候需要人類絞盡腦汁去思考怎麼設計出一個好的 agent 架構。現在反而是人類把所有腦力都投入在設計評測上：你要怎麼精準捕捉你公司、你的政府，或者任何你想最佳化的對象裡，那些困難任務的分布狀況，然後放出這些最佳化器——不管是程式碼最佳化器、提示詞最佳化器、模型權重最佳化器，或是全部一起上——讓它們自己去爬坡、逼近這些評測的高分。這兩個趨勢加在一起，正是我們在 Laude 的 Harbor 開源團隊目前投入大量心力在思考的方向。這很合理。

我很好奇，Open Frontier 是你們投入不少資金在推動的開放研究、開放科學的倡議，這種模式真的有機會跟那些薪資超高、極度保密、不發表研究成果的前沿封閉實驗室競爭嗎？相對於你們正在做的這個開放前沿？謝謝你一個月前在那場會議上的分享。我們召集了大約一百位仍在做開放科學的頂尖 AI 研究者，一起討論了我們所知的科學未來將走向何方，其中一個觀察是，許多頂尖人才正在離開學術界，去追求更高的薪水，從原本三十萬、四十萬美元的年薪，跳到一千萬、五千萬，甚至一億美元的薪資。

從原本能拿到一千萬到五千萬美元經費的實驗室，跳槽到擁有數十億甚至上千億美元經費的實驗室。這兩件關鍵的事，也就是資源的取得，以及現在近乎瘋狂的薪資水準——這對我們十年前創辦 Databricks 時來說根本無法想像——我認為就絕對數字而言，放眼全球，現在有人能拿到十億美元等級的薪酬方案，這簡直是瘋狂。這些正是我對「我們所熟知的科學」感到真正憂心的原因。我相信現在正需要創新，去打造新的制度動能來強化學術界，同時也需要建立一個概念驗證，證明我們有辦法讓研究者擁有足夠的資源，繼續在最前沿做研究。

所以，回到你的問題，明確地說，他們能正面競爭嗎？不能，正面對決是不可能的。我們永遠不會有一個非營利組織，能靠慈善捐款加上美國政府資助——也就是非營利研究的資金來源，包括我們現在所在的這所大學——募到跟 Anthropic 或 OpenAI 同等級的上千億美元資金，但他們確實需要至少多募到一個數量級，也許是一到兩個數量級的資金，這也代表募資的方式需要有全新的樣貌，並且可能需要一種學術界過去從未真正經歷過的實驗室合作模式。也許可以思考一種「實驗室的實驗室」架構，介於學術實驗室目前的合作方式——大多是靠讀彼此的論文、在彼此的想法上疊加發展——以及 Meta、OpenAI、Anthropic 那種中央集權、所有人力都聚焦在單一技術堆疊、單一模型上的模式之間，找到一個折衷點。

介於兩者之間，會是一種比較鬆散、但仍然方向一致的多實驗室合作模式，比如做評測的 Harbor，或做預訓練的 Marin——這是史丹佛由 Percy Liang 主導的專案——或是像 Graham Neubig 在卡內基美隆大學做的 agentic 框架，還有像 Matei Zaharia，或柏克萊與麻省理工的 Omar Khattab 在做的提示詞最佳化與情境最佳化。所以你會看到所有頂尖實驗室的教職人員，再加上獨立研究者，現在都投入到非營利研究裡，這股勢頭正在爆發，雖然規模比不上 Anthropic，但可能是五個人、十二個人的小團隊，甚至連新創實驗室都稱不上，是真正的非營利組織，而不是營利公司。如果你能想辦法把這群各行其是的人聚在一起——先讓他們的臉出現在同一張投影片上——我認為接下來就能真正把它落實運作，這正是我們現在努力在做的事。

比如你們多久聚會一次？大家怎麼在成果產出上達成共識？你們要怎麼取得 Marin 產出的模型？或者要怎麼跟那些正在推出開放權重模型的實驗室合作，像是 Thinking Machines，或者 Reflection，據說也在做一個開放模型，準備在不久的將來釋出。所以要怎麼跟這些團隊合作，讓整體的成果大於各部分的總和，而且還是在非營利的架構下做到？這就是 Open Frontier 在做的事。而且現在確實有一股很大的動能與能量正在匯聚，我們談這件事已經談了大概一年，現在連 Satya Nadella 都在推文上談到這種模式的必要性。Databricks 也在向大家展示，這個開放生態系真的有機會站得住腳。所以我對這件事真的非常投入，非常、非常興奮。
