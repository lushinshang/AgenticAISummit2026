## [11:05 AM] 爐邊對談

**講者**

- Ali Ghodsi（Databricks 共同創辦人暨執行長） —— 對談嘉賓
- Andy Konwinski（Databricks、Perplexity、Laude Ventures 共同創辦人） —— 對談嘉賓

### 軟體從來不會一夜變心，直到大型語言模型出現

過去，軟體有一個大家心照不宣的常識：它有黏著度。使用者一旦上手，就會一直用下去，就算產品開始走下坡，衰退也是緩慢的，人會慢慢流失、慢慢遷移，不會一夕之間全部倒戈。Ali Ghodsi 在對談裡點出，這條規則在大型語言模型身上完全失效——Databricks 因為同時代管專有與開源模型，手上握有完整的切換資料，看到的現象是：只要有新模型上線，短短幾天內使用者就會集體轉台。這不是產品忠誠度的問題，而是模型本質上是隨機的，你問同一個問題兩次都可能拿到不同答案，黏著度原本就無從建立。

但故事沒有停在這裡。Ali 接著指出，鎖定並沒有消失，只是往上移了一層：使用者不會黏著模型，卻會黏著包在模型外面的 harness（代理執行框架）——它的介面、記憶功能、快捷鍵，一旦習慣了就很難換掉。Databricks 今年夏天推出的開源專案 Omnigent，賭的正是這個判斷：與其讓某一家公司的 harness 變成新一代的封閉平台，不如做一個「harness 的 harness」，讓使用者可以在 Claude Code、Codex、OpenCode、Pi 之間自由切換，同時保留社群開發的力量。這個賭注下得不算保守——專案推出兩週，GitHub 上就累積了一千個 fork，幾週內湧入數百名貢獻者。Ali 把這件事放進一個更大的脈絡裡看：Spark 生態系當年撐起了 Databricks 這家公司，開源社群做出來的東西，永遠比任何一間公司自己能做的都大，所以開放介面、開放標準，一直是他認定的策略主軸，而不是選項之一。

### 當「怎麼寫」不再重要，重要的變成「怎麼定義清楚」

兩人談話很快從「要不要開放」轉向「軟體本身還剩下什麼」。Ali 拋出一個判斷：只要你能把程式該做的事講清楚，又有測試和 harness 撐著，具體怎麼實作已經不重要了，AI 會自己找出最快、最好的做法，甚至可能一次又一次重寫。他甚至猜想 GitHub 會演化成一種新型態——pull request 裡裝的不再是程式碼，而是提示詞，審查者要做的，是去執行那些提示詞，判斷這段程式碼有多少比例是人寫的。

Andy 沒有反駁這個方向，但他加了一個關鍵但書：這一切成立的前提，是你要有一套非常嚴謹、滴水不漏的方式去定義規格（spec）。這句話聽起來像附和，其實是把 Ali 的樂觀願景釘在一個更硬的地基上——如果規格本身寫不清楚、評測本身有漏洞，AI 自己找出的「最快最好」實作，優化的可能只是一個錯誤的目標。這也是整場對談裡兩人分工最清楚的地方：Ali 描繪願景的輪廓，Andy 負責檢查地基牢不牢。

### 評測產業正在說謊，而且說得很有規模

這個但書不是空話，Andy 花了對談後半的大半篇幅，具體攤開評測（evals）這個地基有多不牢靠。他的判斷是：前沿實驗室太執著於邁向「超級智慧」，評測重心壓在 HLE（Humanity's Last Exam）那類極端複雜的數學與物理題目上，但企業每天真正要做的任務，根本不在那個評測範圍裡。Databricks 自己蒐集了內部超過一千筆的真實工作問題，做出一個叫 Office QA 的評測——名字取自電影《Office Space》裡那份人人厭惡的 TPS report。結果很有意思：這些題目在難度上其實一點都不極端——像是「掃描一九四〇年代美國預算 PDF、找出當年國防支出」這種平凡的企業任務——但模型在最難的一批只有大約百分之二十正確率，中等難度也只有大約百分之四十。原因是所有訓練心力都投在可以用強化學習硬練的數學物理題上，沒人在乎這種瑣碎但真實的工作。Databricks 用 Office QA 訓出的 PDF 解析 agent，後來把正確率做到接近百分之八十。

Andy 在 Laude 這邊推動的兩個專案，則揭穿了評測產業更根本的問題。一個是 K-Prize：他在 NeurIPS 現場直接開出一張支票——一百萬美元，發給第一個在他們稱為「無污染 SWE-bench」上做到百分之九十正確率的團隊。防污染的做法是承諾在所有人交件之後才開始蒐集題目，用參賽截止日之後四個月新出現的 GitHub issue 來評測。結果最終成績只有大約百分之十，對一個全新基準測試來說已經不錯，但更值得注意的是後續：他們發現幾乎每個基準測試都會被刷到飽和，一路衝到百分之九十以上，而新版一推出又立刻掉回百分之十，然後整套題目又要重來一次。另一個專案是 Terminal Bench，跟史丹佛的 Ludwig Schmidt 團隊合作——Ludwig 做過 CLIP 與 DataComp，DataComp 的思路正是反過來：固定模型與 agent、改變資料集，看誰能把同一個 agent 餵得更好。Andy 在這裡點出一種「地下文化」——熟悉 Terminal Bench 2 的人才知道，那個百分之八十三其實已經等於百分之百，因為裡面本來就摻了一些無解的題目，製作者卻沒把它拿掉。他直接點名這就是古哈特定律（Goodhart's Law）在現場發生：任何指標一旦被拿來當目標追逐，就會被鑽漏洞而失去意義。

他們的解法，是把基準測試當成軟體來寫，而不是每次推倒重來的紀念碑：像修 bug 一樣，拿掉已經飽和、大家都能答對的舊題，換上十道更難的新題，兩三週就能發布一個小版本。Terminal Bench 3 之後會接著推出 3.1、3.2 這種漸進更新，而不是每次都是全新的 3.0。這也連到另一個正在成形的前沿議題：reward hacking（獎勵駭客）。一年前幾乎沒人談這個，現在越來越多人開始針對它設計題目，讓 agent 學會辨識這種鑽漏洞的行為。Andy 的結論是，一旦你有好的評測，agent 與 harness 的程式碼會越來越自動地被最佳化——這跟早期 LangChain、LangGraph 那種要靠人腦硬想 agent 架構的時代完全不同，人的心力現在要花在「怎麼精準捕捉真正困難的任務分布」上，而不是設計架構本身。

### 兩種樂觀，底下是不同的焦慮

對談後段轉向一個更尖銳的問題：開放科學，還能不能跟那些薪資極高、極度保密的封閉前沿實驗室競爭？這一段是全場立場差異最明顯的地方。Andy 給出的答案很直接——正面對決不可能。他攤開數字：頂尖研究者的年薪從三十萬、四十萬美元，跳到一千萬、五千萬，甚至一億美元；實驗室的經費從一千萬到五千萬美元的量級，對比對手數十億甚至上千億美元。一個非營利組織靠慈善捐款加美國政府資助，永遠湊不出跟 Anthropic、OpenAI 同量級的資金。他提出的出路，是一種介於「學術界各自為政、只靠讀彼此論文往前疊加」和「Meta、OpenAI 那種所有人力聚焦單一堆疊」之間的折衷——鬆散但方向一致的多實驗室合作，像做評測的 Harbor、做預訓練的 Marin（史丹佛 Percy Liang 主導）、CMU Graham Neubig 的 agentic 框架，把這些各行其是的團隊先拉到同一張投影片上，再想辦法讓整體大於部分之和。這是一個建立在資源結構性弱勢之上的解法，語氣裡帶著急迫感。

Ali 的樂觀則建立在完全不同的時間尺度上。他用歷史類比回答「大學生念資訊科學還有沒有希望」這個問題：電動馬達早在一八四〇、五〇年代就存在，但要等到一八八〇到一九二〇年，它才真正取代蒸汽引擎、反映在 GDP 上——不是因為技術不成熟，而是因為改變整個社會運作方式本來就需要幾十年。網際網路二〇〇〇年就已經存在，但 Airbnb 的點子要等到二〇〇九年才被想出來，而且完全不需要新的實體基礎設施，純粹是想法滲透社會需要時間。他因此判斷，這場代理型（agentic）革命至少要花上十年，甚至更久——公司才成立十三年的 Databricks，光是盤點自己內部所有正在做的事就已經很不容易，外面還有存在了五十年、一百年的組織。順著這個邏輯，他描繪的不是焦慮，而是巨大的空白：未來會出現一家能讓你找到「看過數十億個病人」醫師的醫療保健公司，價值可能上兆美元；教育這個過去創投認定賺不到錢的領域，也會因為這項技術被重新定義，因為選舉輸贏往往就繫於教育議題，家長對孩子的教育有多在乎不用多說。

同一個問題，Andy 給出的答案落在更貼近地面的地方。他仍然和柏克萊、史丹佛、麻省理工的博士生一起工作，觀察到這些學生會拒絕封閉實驗室開出的一年五百萬、一千萬美元薪酬方案——那種可以進去做前沿研究、形塑 Claude 運作方式，但永遠不能公開談論的機會。理由不是不缺錢，而是他們清楚，能把自己認定有價值的問題做出來、並承諾分享給全世界，這種影響力最終比支票更重要，支票只是一個落後指標。兩人給出的答案殊途同歸——資訊科學沒有沒希望，現在是最好的時機——但支撐這個結論的，一邊是宏觀的歷史尺度，一邊是他每天在博士生身上看到的具體選擇。

對談結束前，Ali 說了一句沒有刻意收尾的話：他真希望自己能晚一點出生，剛好現在二十、二十五歲，正要開始投入這個領域。台下沒有標準答案，兩位共同創辦人也沒有假裝有。
