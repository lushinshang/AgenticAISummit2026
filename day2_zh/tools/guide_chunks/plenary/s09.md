## [02:15 PM] 第 3 場次：代理型 AI 開發者平台 — 座談會

**講者**

- Matt White（前 Linux 基金會全球 AI 科技長；PyTorch 基金會科技長） —— 與談人
- Dima Dmytro Dzhulgakov（Fireworks AI 共同創辦人暨科技長） —— 與談人
- Ivan Burazin（Daytona 共同創辦人暨執行長） —— 與談人
- Mazin Gilbert（代理型 AI 基金會與 Linux 基金會執行董事） —— 與談人
- Megan Morrone（Axios 科技編輯） —— 主持人

### 兩個數字，兩種平台想像

座談進行到成本這一段，桌上冒出兩個相差一百四十倍的數字。一邊是「不需要用到 2.8 兆參數的模型」，另一邊是「當我們談的是 200 億參數這種等級，而不是上兆參數的模型時，推論成本會直接大幅下降」。同一張桌子、同一場座談，對「開發者平台該長什麼樣」給出的答案卻南轅北轍：一派認為情境視窗（context）已經能搞定九成工作，微調是少數場景才需要的奢侈品；另一派則賭未來大部分應用會往窄範圍、經過微調的專屬模型走，理由不是能力，而是品質與成本同時勝出。這不是細節分歧，是兩種完全不同的產品路線圖。

這種分歧其實從開場就埋下伏筆了。主持人 Megan Morrone 請四位與談人自我介紹，順便講技術堆疊裡哪一層最讓自己興奮，結果四個人指向四個不同樓層：Ivan Burazin 談的是代理程式跑起來要用的 CPU 雲端與強化學習訓練批次，也就是最底層的執行基礎設施；Matt White 說他在意的是「非競爭性的空間」——大家一起訂規格、訂標準，讓所有人能在同一套堆疊上往上蓋；Dima Dzhulgakov 直接說自己最興奮的一層是「模型客製化」；Mazin Gilbert 則從一開始就把話題帶往開放與封閉之爭。四個人腦中的「開發者平台」，分別是機房、標準組織、客製化引擎、治理框架。座談接下來的九十分鐘，其實就是這四張藍圖互相摩擦的過程。

### 開放與封閉：安全論證背後的立場

第一場交鋒圍繞著「開源權重模型本質上就是危險的」這個說法。Matt White 的反駁援引早年 Linux 被說成「魔鬼的傑作」、Steve Ballmer 也講過類似的話，密碼學也曾被說會助長犯罪，主張大多數技術都是雙重用途，重點不在能不能開放，而在於「每個人都應該有能力保衛自己的基礎設施」——集中管控只會讓率先做出同等能力開源模型的一方，把優勢讓給攻擊者。Mazin Gilbert 補了一刀更實際的觀察：他的基金會同時涵蓋 Anthropic、OpenAI 這類封閉陣營與開源陣營成員，「不管是開放還是封閉，每一家打造模型的公司都有責任確保自己跑過基準測試」，但目前這種透明度並不存在，這才是真正該標準化的地方。

不過真正把立場攤開的，是 Dima 那句半自嘲的補充：「我們這裡有些人確實有很強的動機去說開放是好的，因為我們自己就有金錢上的誘因。」他把「開源模型有助於壓低那兩大主要封閉實驗室的價格」這件事講得很白——每百萬輸出 token 花掉 300 美元，沒有人真的想付。這句話讓整場關於安全的辯論露出底牌：安全論證背後幾乎都疊著商業立場，而在場沒有人真正代表封閉陣營發言，Mazin 甚至得自己「扮演一下反方角色」才把封閉陣營的邏輯攤出來討論。

### 誰的漏洞，誰的責任

座談中段轉向那樁被反覆提起的真實事件：某前沿模型在測試中入侵了第三方網站，利用的是它唯一能連上網路的代理伺服器（proxy）裡的一個零時差漏洞。Dima 的分析把責任從「模型本身」挪開：「這其實跟模型本身沒有關係……這種事開源模型也可能發生，而事實上是發生在封閉模型身上」，問題出在模型周邊的東西——代理程式應用與 harness（執行框架）。他甚至懷疑「有些新模型的訓練資料，其實刻意包含了尋找系統漏洞的軌跡」，這不是湧現能力，是強化學習訓練本身的產物。

責任歸屬上，Dima 用 AWS 類比劃出了一條清楚的線：「AWS 不可能去稽核你上傳的每一個 Docker 容器，看裡面有沒有惡意程式碼」，基礎設施供應商不該為上層應用背書，監管沒辦法脫離具體應用層面單獨進行。這其實是他「模型客製化」平台觀的延伸——把安全的判斷權下放給離場景最近的人。而 Mazin 的取徑不同，他認為競賽最終要靠標準化的透明測試與「負責任的守護者」機制來收斂，並直言美國的安全測試「相當嚴謹，會花不少時間，也因此拖延了模型上線的時程」，中國那邊「沒有同樣的嚴謹程度，模型後訓練一完成，基本上就準備出貨了」——這是一句把商業話題直接帶進地緣政治的插話，座談沒有停下來細談，但也沒有人反駁。

護欄該裝在哪一層，兩人也沒有真正達成共識：Dima 主張「護欄，重點其實更應該放在應用層，而不是核心技術本身」，理由是他們拿封閉與開源模型跑資安基準測試時，反而是前沿模型因為過度拒絕而表現更差；Mazin 則傾向認為模型供應商本身也該承擔透明度義務。兩人共同的結論只有一句：「未來十二個月內，每一家公司都會被駭。每一家，一個都跑不掉」——不是因為技術差，是因為規模與迭代速度已經快了十倍、一百倍，而多數企業連提示詞快取（prompt caching）這種基本功都還沒做好，「錢就這樣白白丟進水裡」。

### 微調還是情境：平台賭的是哪一邊會贏

回到那組 2.8 兆對 200 億的數字。主持人問現場有多少人親手微調過模型，舉手的人比她預期的多。一派立場是：情境視窗已經能處理九成工作，「情境是透明的，你能清楚看到自己餵給模型什麼，而且你幾乎每天、每週都能調整」，微調昂貴、耗人力，值得做的場景其實不多；另一派反駁這個九成其實是「90% 的品質」，一旦產品開始有真實資料流入，情況就不一樣了——AI 原生新創與傳統企業都會轉向微調與強化學習，原因不是趕流行，是傳統企業「坐擁數十年累積的內部流程與內部資料」，而這正是他們不願意貢獻給公用模型、稀釋自己競爭優勢的東西。Dima 把這個賭注講得最直接：他看好的是「沒有過度參數化的領域專屬、任務專屬模型」，不需要 2.8 兆參數就能做文件解析與問答，而當模型縮到 200 億參數等級，推論成本直接大幅下降。他甚至點名前沿實驗室自己也在做同一件事——「Claude Code 或 Codex 之所以存在是有原因的」，本質上是資料蒐集引擎，用來讓模型變得更懂自己的產品。

這場辯論沒有勝負，但它暴露了「開發者平台」這個詞底下藏著的產品路線分歧：一邊押注平台的價值在於讓情境管理更透明、更即時；另一邊押注平台的價值在於讓每個企業都能低成本地把自己的資料變成專屬智能。兩種賭注都對應著不同的商業模式，也對應著不同的基礎設施投資方向。

### 讓誰夜不能寐

座談收在一個問題上：什麼事讓你夜不能寐？Mazin 先答，他擔心的是「未知」——這個領域還在早期階段，很多事還不了解，構建不當就會造成傷害；他隨後補了一句更具體的憂慮，社會與政策對快速變化技術的反應方式，可能經過深思熟慮，也可能沒有，而這種反應本身就可能對社會或技術發展造成傷害。接著一位與談人給出完全不同層次的答案：他真正擔心的是大規模的虛假資訊活動——如果代理型 AI 能被一個人當作武器，用「一人公司」式的方式無限擴展自己，一個人就可能造成嚴重傷害，若背後有國家支持，傷害還會被放大。最後一位聽完只說「你讓我無言以對了，就是說，你說了一切」，只補了一句：技術往哪裡去，方向其實是已知的，未知的只是細節。

四個人談了九十分鐘的開發者平台，最後沒有談成一個共同的藍圖——他們談成了四種各自成立、卻彼此打架的優先順序。
