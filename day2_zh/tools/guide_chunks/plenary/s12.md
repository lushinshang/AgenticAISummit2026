## [03:50 PM] 新創焦點

**講者**

- 精選新創：Narada AI, cognee, Nimblemind, AgntID, RELAI, Headroom, Founding Dev, ArmorIQ, Keenable AI, H Company, Ludo Robotics, Nimble

### 十二場簡報，沒有一家在賣更聰明的模型

這是整場高峰會的壓軸環節，也是份量最重的一節：十二家新創輪番上台，每家幾分鐘。把十二份簡報攤開來看，會得到一個有點掃興的結論——經過兩天前沿模型的討論之後，收尾的這一節裡，幾乎沒有一家公司在賣「更聰明的模型」。Headroom 的創辦人把這句話講得最白：「代理沒有推理的問題，它們有的是情境的問題。」cognee 的創辦人講法不同但意思一樣：「這個問題，從我們的角度來看，其實不是一個 Agentic 問題，而是一個資料問題。」H Company 說得更直接：「AI 領域目前最大的轉變，其實不在模型本身，而是在代理能力與電腦操作能力上。」三家公司、三種產品，講的其實是同一件事：模型的推理能力已經夠用了，卡住代理的是它周圍那一整圈——身分、存取權限、記憶、搜尋品質、介面——沒人管的灰色地帶。這批新創，做的幾乎都是把這些灰色地帶一塊一塊補起來的工作。

### 沒有 API 的地方，才是真正的戰場

Narada AI 和 H Company 站在同一道題目的兩端。Narada 的切入點很具體：企業裡真正卡住人力的，不是那種簡單的 co-pilot 型任務，而是像 ERP 測試、跨資料孤島的核對、橫跨多個舊系統的訂單與帳單處理這類長流程作業。這些流程之所以還靠人工，是因為很多步驟根本沒有 API——只能透過使用者介面點擊、輸入、捲動。寫死的腳本一遇到介面變動就故障，通用型模型又會在正式環境裡遇到登入失敗、逾時、重複資料這類現實例外時開始產生幻覺。Narada 給的答案是把「學會一個介面」和「重複執行這個介面」拆成兩個階段：先花成本繪製並學習客戶環境，之後同樣的流程用少得多的運算資源、更高的準確度重複執行——他們提到某客戶有 4,000 個沒有 API 的帳單入口網站，正是這套邏輯要解決的規模問題。

H Company 從研究端講同一個問題，但格局拉得更大。他們把「電腦操作能力」定義成一種跟 RPA 本質不同的技術：RPA 是在靜態環境裡執行寫死的腳本，電腦操作能力則是理解情境、適應介面變化、動態行動。他們的論點是，運算與生產力領域每一次重大躍進，靠的都是掌握一個新介面——終端機、桌面、瀏覽器、試算表——而 AI 到目前為止一個介面都沒真正掌握，能思考、能對話，卻無法在企業實際工作發生的地方運作。今年稍早他們宣布以十分之一的成本在電腦操作基準測試上超越其他前沿實驗室，並完成當時歐洲規模最大的種子輪，兩億兩千萬美元。這兩家公司其實在賭同一件事：等到每個工作流程都被重新用 API 建構一遍，代價太高，不如直接讓代理學會用眼睛看螢幕。

### 記憶、情境、搜尋——供給代理的是資料，不是答案

如果沒有 API 這一塊解決了「代理能不能動手」，接下來這四家公司解決的是「代理拿到的資訊夠不夠格」。cognee 把這個問題定義成「代名詞問題」：一句話裡的「他」，在不同情境裡指的是不同人，企業裡的營收定義、財年、業務用語也一樣，脫離脈絡就會出錯。他們用向量加知識圖譜疊出一套會隨時間演化的資料層，架在 Postgres 之上，號稱比把整段上下文硬塞進模型省下 86% 的 token。Headroom 從反方向處理同一個問題：他們在用 Claude Code 除錯 GPU 問題時發現，九成的情境都花在讀取跟提示詞無關的資料上，於是做了一個攔在代理與工具呼叫之間的本機代理伺服器，把冗餘壓縮掉，但留一個可以回頭取用原始資料的「麵包屑」。他們公布的數字是在程式碼代理上省 15% token、資料代理上省 60%，準確度幾乎不掉——七個月內拿到六萬四千顆 GitHub star，兩百萬名開發者在用，客戶名單裡有 Yahoo、摩根大通、沃爾瑪。

Keenable AI 和 Nimble 則把矛頭指向搜尋本身。Keenable 的創辦人講了一個現象：問 AI 一個你外行的問題，答案完美；問一個你懂的問題，答案變得平庸，因為模型缺基準測試資料，卻還是給出一個毫無依據卻極度自信的建議。他給的數字是，ChatGPT 大約每三則訊息才查詢一次、每產生五千個 token 才搜尋一次，搜尋成本占了每一塊錢裡的兩毛——現有的網路索引全是為人類的查詢習慣最佳化的，而代理提問的方式跟人完全不同：精確、帶引號、指定網站。Nimble 講的是同一個瓶頸的另一面：與其用一個通用檢索系統回答所有問題，不如把搜尋系統拆成一個個專門化的小模型——他們提到用十億到二十億參數等級的模型做特定領域的檢索，而不是丟一個巨大的通用模型去撈資料。兩家公司分別攻搜尋的「經濟性」和「精準度」，但共同的判斷是一致的：通用搜尋系統沒辦法隨著代理的規模擴張，這件事得重新設計。

### 兩家公司站在同一道牆前，卻用了兩套完全不同的詞彙

AgntID 和 ArmorIQ 是這一節裡最有意思的對照組——他們解的其實是同一個問題，卻連怎麼命名這個問題都還沒有共識。AgntID 的開場示範很直白：你請代理去摘要一份 Google Doc，這代表它應該只能讀那一份文件；但代理有時候會「過度積極」，跑去看別的文件，甚至把「讀取」的意圖執行成「刪除」的動作。他們的解法叫「僅限任務」的執行期存取權限——代理永遠拿不到一張全權通行證，而是先用意圖評估縮小範圍，再用政策評估進一步縮小，真正動用權限時還會換發一個範圍更小的權杖。他們把這句話當座右銘：「意圖加上政策等於存取權限。」

ArmorIQ 講的幾乎是同一件事，卻選了完全不同的入口。他們的開場是一句話：「重點不在身分，通過身分驗證不代表行為就是對齊的。」——現在部署在正式環境的每個代理都有身分、也通過了安全檢查，但還是會做出不該做的事。他們原本想稱自己是「身分治理」，講者在台上說錯又立刻改口：「抱歉，是意圖治理方案。」這個口誤本身就說明了問題——這整個領域連自己在做什麼都還沒有統一的講法。AgntID 把自己定位成基礎設施採購者（身分管理、資安、DevOps）要買的東西，盡量繞開開發者；ArmorIQ 則想把自己做成一套獨立的「意圖保證協定」，擴大到代理後續的所有行動，而不只是第一步的存取判斷。兩家公司、兩種語言、同一道牆——這通常是一個訊號：這塊市場還早，還沒人真正把問題定義清楚，大家都還在各自摸索該用哪一套詞彙去賣同一個東西。

### 代理會失敗，重點是修的時候別靠猜

RELAI 處理的是前面幾家都沒碰的一塊：代理已經上線之後，怎麼讓它持續變好而不是持續累積壞習慣。他們指出現在業界的做法本質上是「猜」——發現代理失敗，人工檢視，派一個編碼代理去改，但沒人知道這次修改會不會在其他情境裡造成看不見的退步。RELAI 的做法是把代理的每一次行為都轉成可重播的學習環境，先做根因分析，找出「最小且持久有效」的修改，再用一個會控管退步的最佳化器去改。他們拿一個延伸自 TerminalBench 的測試驗證這件事：第一階段十二個困難任務、第二階段十個困難任務，測的是最佳化的效果會不會「複利」——先前的進步是否能在下一輪繼續疊加。他們發現常見的 meta-harness、GEPA 這類方法，不是無法持續改進，就是在兩階段之間出現負向遷移，而 RELAI 的方法在兩階段都有明顯進步。這一家公司補的洞，其實是所有前面提到的「代理自主行動」的公司都需要的保險——你讓代理去操作螢幕、去查權限、去搜尋，遲早會出錯，出錯之後怎麼修，不能只靠賭。

### 專科化才是真正把數字做出來的地方

如果說前面幾家都在解決「讓代理能用」的基礎問題，Nimblemind 和 Founding Dev 則示範了「用出真金白銀」長什麼樣子。Nimblemind 從一個很硬的產業事實切入：美國醫療支出裡，跟臨床照護完全無關的行政作業就占了約 25%，換算下來是六千億到一兆美元。他們不做一個通用的醫療模型，而是為腫瘤科、病理科、放射科、腎臟科這些專科各自訓練專屬模型，再組合起來運作。他們提到跟新加坡保健集團合作的案例：檢視超過兩百萬份病理報告找漏診的幽門螺旋桿菌與胃炎案例，人工每一千份報告要花八十二小時，他們把整個工作量壓縮了超過 99% 的時間，而且準確度高於對方內部團隊原本能接受的門檻，整個專案不到一週完成。

Founding Dev 的切入點是中小企業：一家企業每年花在租用 SaaS 上的錢動輒二十萬美元起跳，他們讓客戶用自己的工具取代那些訂閱，省下 70% 成本。他們舉了一個具體案例：猶他州一位教育顧問，原本每年花十三萬五千美元養外包團隊做內部工具跟系統整合，換成 Founding Dev 之後全部收斂到一個平台，省下來的錢拿去做行銷，新簽了三十個學區客戶。他們的商業模式很直白：每月兩千到七千美元不等，目前年經常性收入接近五十萬美元，每個月新增十萬美元——這兩家公司談的都不是技術有多先進，而是這一整套代理基礎設施補齊之後，到底能不能換成看得見的錢。

### 身體已經夠用了，缺的是懂人

Ludo Robotics 站在這批公司裡一個略顯突兀但邏輯相通的位置。他們把機器人聰明程度拆成兩個維度：身體上聰明、社交上聰明，現有的機器人大多落在「身體聰明、社交笨」那一格——適合工廠裡有柵欄圍住的環境。他們的判斷是，與其等一個兩個維度都頂尖的機器人出現，不如反過來想：如果直接拿現有身體能力的機器人，加上很好的社交智能，會怎麼樣？他們展示的示範裡，一台機器人被要求「幫忙確認水燒開了沒、洗衣機洗好了沒」，自己走去廚房查看，回報「衣服洗好了，但水還沒燒開」，還接了一句玩笑：「抱歉，我目前還不會摺衣服，如果我們完成下一輪募資，說不定我很快就會摺了。」這其實跟前面所有公司在做的事是同一個邏輯——不是重新造一個更強的核心能力，而是把已經存在但沒被用好的能力，跟一塊明顯缺失的層補起來。只是這裡缺的那一塊，是懂人。

### 收尾

Berkeley RDI 今年春天招募了八家公司組成加速器梯隊，又邀了四家業界早期公司一起上台，湊成這十二場簡報。串起來看，這其實是整場高峰會兩天下來最誠實的一個切面：當所有人都預設模型會持續變強，真正卡住落地的，從來不是模型本身，而是模型要在真實世界裡動手時，那一圈沒人管的介面、權限、記憶跟搜尋。收尾的致詞裡提到，這個高峰會從 2024 年秋天的一門線上課程開始，到今年辦成兩天、參與人數翻倍的規模——如果這批新創講的是真的，明年這個舞台上要解的問題，恐怕又會是另一圈新的灰色地帶。
