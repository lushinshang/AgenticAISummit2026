**Philip Rathle：** 好的，我來試一下這支麥克風。好，效果不錯。太好了，很高興來到這裡。各位這陣子大概聽了不少關於知識、脈絡、語意、記憶、本體論這類 AI 相關的詞彙。它們某種程度上算是各自獨立的主題，不過我今天要把它們全部串起來，用「知識層」這個主題來談。這是我這幾年和數千位客戶合作後得出的結論，我發現他們把這些東西整合起來運用時，其實有幾種共通的模式。這個模式就是企業知識層。這裡可以看到一張簡單的示意圖：應用程式、代理人、工具存取一個知識層，這個知識層從資料與知識的角度，提供代理人所需要的東西。

它把整個企業各處的資料整合起來，你可以看到右下角是各種營運資料來源，左下角則是各種分析資料來源。這並不是單純的搬遷（lift and shift）。知識不同於資料，並不是指「關於一切的一切」，而是指把訊號從雜訊中萃取出來，再把它們連結起來。這些連結在這裡才是關鍵。同樣地，你可以從小規模開始，再逐步擴大，所以這也是非常漸進式的做法。

如果從功能面來看，它在做什麼？它儲存結構、脈絡與意義，為代理人提供統一的記憶與檢索層，同時也橋接了人類與機器的理解，這又回到「神經符號式 AI（neuro-symbolic AI）」的概念，這概念其實已經有幾十年歷史了，只是現在以圖（graph）這種不同的形式回來了。你去試著檢視一個模型，或檢視一個向量資料庫，這些東西對人類來說是難以理解的；但用圖的話，人類真的可以理解發生了什麼事，同時機器也能執行它。它還能連結並統一你的資料來源與物件，並以圖的形式儲存資料。這裡有幾個實際案例。

第一個是 Walmart 的 People AI 知識圖譜與圖形應用程式。這是一個代理型應用程式，供 Walmart 大約 160 萬名員工使用，協助他們規劃自己的職涯發展。這個圖長什麼樣子？裡面包含所有的人、回報結構、回報結構的歷史、員工的技能、這些技能是如何隨時間累積的、他們參與過哪些專案、目前有哪些職缺開放、以及這些職缺的要求。結果發現，只要把這些全部放進同一張圖裡，就能單純靠連結這些點，來推薦一個人的職涯路徑，這幾乎就像是用「凱文貝肯的六度分隔」的方式在解決人資問題。重要的是，這之後會餵給一個模型，所以人類與圖之間會有一個模型，但問題實際上既可以透過餵給模型更多脈絡讓模型來回答，也可以直接從圖裡得到答案，以確定性的方式執行。

所以你擁有這種強大的彈性，可以選擇用確定性或非確定性的方式來運作。這裡是另一個例子，來自 Uber，他們有一種不同類型的圖，叫做規則圖（rules graph）。Uber 在 1 萬 5000 個城市營運，在這些城市裡提供不同的服務，這些服務的名稱也各不相同，還有不同的法規，以及 Uber 自己因地制宜的各種考量，這些規則都儲存並在圖中執行。我再舉一個例子，來自全球數一數二的大型遊戲公司，你可以看到一個對話式 AI 存取 API 層、存取一個多代理人系統，然後把圖當作語意層來使用。這裡的語意層，指的是把商業術語、概念、以及這些概念之間的關係，對應到實體基礎設施，一路對應到資料基礎設施，讓你知道資料在哪裡可以找到。

所以代理人使用這張圖，取得一份地圖，知道要去企業內部的哪裡尋找資料。所以這是三種不同類型的圖：你可以說這是語意與本體論，前面提到的是領域圖（domain graph），你還有規則圖，這是一種記憶的形式，也就是程序性記憶。而這些公司選擇用這種特定方式建構系統，背後的核心洞察、也是它們的共通點在於：他們發現自己的資料，要嘛以網路的形式呈現，因為在 AI 需要處理的真實與數位世界裡，資料通常會以幾種形式出現。它可能以網路的形式出現，例如電腦是網路連結的、社交網路、通訊、生物學、生態學、交通運輸等等；也可能以階層的形式出現，就像 Walmart 的人資例子，其實那是多重的階層與歷程，同樣地，顧客歷程、病患歷程等等也是如此。

因此你可以選擇用表格來表示這些資料，事實上過去幾十年來這一直是主流做法。但現在有一種更新的資料表示方式，事實上在兩年前已經成為 ISO 標準。對還不熟悉這件事的人來說，這是近 40 年來第一次，國際標準組織（ISO）認可了資料庫領域的一種新資料模型，也就是屬性圖（property graph）資料模型，用來表示我們正在談的這種資料，處理那些在真實與數位世界中以網路、階層、路徑形式出現的資料。那為什麼需要一個新模型？為什麼處理現有的東西不夠？我們來看看你現有的東西是什麼。

你可以使用一個基礎模型，但它們是用全世界的資料訓練出來的，不是用你的資料訓練的。好，那我可以自己訓練一個小模型，但那很昂貴。就算克服了這一點，模型一訓練完馬上就過時了。而且我用來訓練模型的所有東西，之後都會變成可以用來回答任何代理人為任何目的所做的任何決策的素材——而我們都知道，企業內部對存取控制有各式各樣的規範。它還是可能產生幻覺、缺乏判斷力，而且是個黑盒子。以靜態的行與列結構化的資料很好，大部分資料也確實是這樣，這對回答固定且簡單的問題很有用；但如果我的問題變得非常複雜精細，而且我事先不知道下一個問題會是什麼，這時候圖形一直以來就特別擅長處理這種情況。

我做這行超過十年了，這一直是使用圖形技術的主要原因。現在我也可以去看其他非結構化形式的資料，但那往往很難挖掘、也很難理解，就像我前面提到的，向量是完全不透明的，可以說它幾乎只有一兩招可用。而且組織內的資料分散在各個孤島（silo）中，那我要怎麼把跨孤島的知識整合起來，好讓我的代理人能共享整個公司的智慧，而不只是某一個系統裡的資訊？

現在很多公司都在做這件事，做到 Gartner 出面表示：這是一個明顯的趨勢，對資料與分析主管的建議是，他們必須重新設計資料與分析架構，讓脈絡層成為 AI 代理人的核心大腦，以提供值得信賴的智慧。這正是我們今天談的內容。現在來看看代理人對知識有什麼需求。代理人具有高度互動性，所以他們不能只是跟資料湖（data lake）或資料湖倉（lakehouse）互動，他們需要一個即時系統，能有低延遲的檢索，同時也能更新系統，這樣才能形成一個自我改善的良性循環。第二點，你也需要能夠儲存結構化、非結構化以及半結構化的資料。

第三，你需要把跨孤島的資料整合起來。你的資料湖與資料湖倉確實把跨孤島的資料整合在一起，但代價是失去了資料之間的連結——你把一切集中化了，卻沒有把它們連結起來。你需要能有一個 RAG 語料庫，我還會加上一個 graph RAG 語料庫。此外你也需要資料存取控制，原因正是我們前面提到的：企業防火牆、安全性、隱私。這些就是代理人所需要的。現在如果我把這一切整合起來，這其實就能回應所有這些需求。這其實是我們前面談過內容的放大檢視。在最高層級，你有以圖形連結起來的資料，也就是你的領域資料。

那可以是你自己的領域資料，也可以是你從第三方取得的參考資料。而且現在你也可以選擇透過像 Neo4j 這類技術，以虛擬的方式對資料湖執行圖形查詢，所以圖上也有「虛擬圖」這一塊。在本體論這個區塊裡，我把語意層也包含進去，這一塊涵蓋的是所有跟「意義」有關的東西——你的商業意涵，以及它如何對應到你的資料所在位置，這就像是一張商業與技術的地圖。最後、但同樣重要的是記憶。對話式記憶就是所有不同的文字與提示；但就像人腦一樣，睡眠與記憶鞏固的過程，會給你長期記憶，也就是哪些事情才重要、它們彼此如何連結。

長期記憶通常最適合以圖形儲存，程序性記憶也是，另一種記憶形式——決策軌跡（decision traces）——同樣也是如此。那知識層的角色是什麼？這其實是一整場演講的內容，我把它濃縮成一張投影片，因為我們時間不多。最後我會給大家一些學習資源。第一點，它為代理人提供脈絡，讓答案更好。我會給大家看一篇剛發表的論文連結，來自英國的資料與 AI 中心，這是一篇相當豐富的學術研究，顯示效果顯著提升——我記得能回答的問題數量多了一倍以上，準確度提升 80%，幻覺更少，用的 token 也更少。所以效果非常非常強大。

它可以連結各個孤島，帶給你知識的透明度，並提供確定性處理的選項；它可以遵守資料存取控制，而且讓我意外的是，它處理複雜問題的能力也大幅提升。一個又一個客戶回來告訴我，AI 模型在用圖形查詢來回答以人類語言表達的複雜問題時，表現遠比用關聯式查詢好得多，這是因為圖形查詢語言——GQL 或 Cypher——你可能用五行就能表達一個複雜問題，而這在 SQL 裡可能要寫兩百行，這是一種更精簡、更貼近人類語言的表示方式。那企業裡具體有哪些種類的資料？有兩種看待方式：一種是廣度優先或由上而下的視角，把整個企業本身看作一個相連的有機體，你可以建立一張地圖，把各個孤島連結起來。

另一種是由下而上的視角。這裡你可以看到有一張產品圖，也就是產品階層，從中衍生出下面各種被支援的應用場景，例如推薦、產品定價、庫存。但如果你把它連結到供應商資料，就可以做供應鏈最佳化等等。我們前面看到了員工圖、職涯歷程等等。你可以逐步地把這些擴充建構出來。我沒有太多時間細講這個，但我會快速帶過去。這張圖是在看目前排名前面的 AI 應用場景，這些資料來自頂尖系統整合商與一些頂尖 AI 實驗室，對應到會出現的各種圖的類型，也對應到被啟用的各種 AI 動作與流程類型。

你會在裡面看到像多跳推理（multi-hop reasoning）與代理型工作流程這樣的東西。深入談推理這一塊，我今天想留給大家的一個重點是：知識層不只是一個被動儲存資訊的地方，它其實可以進行各種形式的運算。我時間有點趕了，會快速帶過這幾點：圖形查詢，也就是各種形式的模式比對與篩選；圖形演算法，像是分群、連結預測等等；相似度搜尋；圖神經網路（GNN），這是一種拓撲向量、也是另一種向量；還有圖形視覺化。而這裡的關鍵優勢包括：GraphRAG，能提升準確度；多跳推理，能幫助代理人執行更複雜的任務；語意地圖，也就是企業的地圖；決策軌跡，這本身就足以獨立成一場演講，我會給大家一些線索；還有記憶。

那我留幾個資源給大家，然後我們就進入下一位講者。第一個是我兩年前寫的一篇文章，內容至今依然適用，介紹 GraphRAG。第二個是兩週前剛發表的文章，描述企業知識層，可以說是把今天這場演講用文字散文的方式呈現出來。第三個就是我剛提到的那篇論文，顯示使用 GraphRAG 的代理人，相較於只用向量的代理人，真實性高出 80%，能回答的問題多了一倍，幻覺更少，而且成本更低——用的 token 少了很多。最後、但同樣重要的是，如果你掃描這個 QR code，我們為大家準備了一個特別的登陸頁面，裡面有更多進一步的學習資源。其中一項是，Andrew Ng 今天也在現場。

**主持人：** 好，謝謝 Philip。接下來，我們邀請 Imbue 的 Josh Albrecht。歡迎。

**Josh Albrecht：** 好，按鈕在哪裡？這個是進階版。太好了。

好，今天我們要來談談打造開放軟體、打造龐克軟體（punk software）的重要性。我們今天聽到的很多演講，內容都是關於這些很酷的平台之類的東西，那些都很棒，但事實上你幾乎可以自己動手打造任何你想要的東西，這就是我們今天要談的主題。我很喜歡這句話，拿來當開場。這句話是：「此刻，曾經是那個難以想像的未來。」這是 Long Now Foundation 的 Stuart Brand 說的。我想如果你回到五年前，去問人們、或告訴人們我們今天用編碼代理人可以做到什麼事，他們大概會說：你在講什麼？這不可能發生。

事情發展得非常快，我們現在有了 AI 代理人，讓我們可以去思考、去夢想、去創造那個五年後才會到來、如今難以想像的未來。但今天，前沿 AI 完全被少數幾家公司掌控，而且存在著不少假設性的風險。舉例來說，如果有一家 AI 公司發布了一個像 Fable 這樣的模型，然後又把它下架了呢？如果他們大幅漲價呢？如果他們把你的帳號封鎖了呢？如果他們修改服務條款，讓你不能再做原本在做的事，比如說 AI 研究呢？你的事業能撐過這些事件嗎？你在做的、你在乎的東西，能撐過這些東西突然從你身邊消失嗎？

但這些風險其實已經不再只是假設性的了。像現在最大的一些 AI 實驗室，已經開始例行性地隱藏其 AI 代理人的思考過程、隱藏 logits，讓第三方稽核變得更困難；就像我們一兩週前看到的那樣入侵你的網站；拒絕協助你修補漏洞，拒絕在網路安全防禦上提供協助；像我們幾週前在 Anthropic 身上看到的那樣，悄悄地降低效能；像我們看到 Anthropic 那樣，在跟人合作後，反過來自己做藥物研發，或是在跟 Figma 合作後自己做出雲端程式碼設計工具，來跟你的事業競爭；又或者，在沒有任何申訴管道的情況下封鎖你的帳號。所以 AI 對你來說確實存在一種存在性風險——不是對整個人類來說，我們不會因此滅絕——但你的事業與生計，卻真的可能因此消失。

所以我認為，如果我們想要一個美好的未來，我們的想法、以及我們代理人的想法，都需要完全在我們自己的掌控之下。這不能是我們依賴某個第三方遠端電腦來提供、而且隨時可能被關掉的東西——如果我們是這樣想的話。如果我們要用這些工具來做教育、來打造我們用來經營生活與事業的自己的工具，我們就不能容許有一部分東西其實不是真正屬於我們自己的一部分。那我們該怎麼做到這一點？我認為我們需要讓整個技術堆疊都開放。所以現在是時候發起一場自由軟體革命，把控制權奪回來，這就是龐克軟體（punk software）的意義所在，這是一場軟體起義。

那什麼是龐克軟體？其實這個詞是我們隨口編出來的，當時有人在 Twitter 上私訊我們說：「我超喜歡你們的龐克軟體風格。」我們就想，好啊，那就用這個詞吧。我們說的龐克，指的是去中心化、極簡、自己動手做（DIY）。與其說是一套規則，不如說更像是一種精神或氛圍，一種看待軟體的方式。原本的龐克音樂運動，很大程度上就是關於自己動手做——就算你不太會彈樂器、不太會寫程式也沒關係。我們想把這種精神帶到軟體上。我們所謂的龐克軟體，指的是你自己打造的軟體，你可以分享它，可以幫助別人一起打造它，它應該是你能理解、能探索、能創造、而且真正屬於你的東西。

那什麼樣的軟體算是好的龐克軟體？我認為有五個要素。第一，個人化。我的意思是，它是完全由你掌控、完全屬於你的一部分，同時你也可以客製化，讓它更貼近你自己。你能掌控它的一切嗎？現在有這麼多開放原始碼軟體，這是有可能做到的。我們也希望它是去中心化的，不會輕易就被關掉，不是跑在別人伺服器上的東西，而是無所不在、分散各處的。這其實就是我們所說的「民主化」與「賦權」的真正意涵——就是你真正擁有屬於自己的工具，讓你能做自己想做的事。

第三，我們希望這些東西是開放的。我們希望軟體不只是開放原始碼、你可以讀到程式碼，也不只是開放權重，而是在這樣的意義上開放：你可以真正看到模型內部、你的系統內部、你的作業系統內部，究竟發生了什麼事，並理解其原理。你可以學習、自我教育，並在這之上建構更大的系統。而這種開放性還有另一個附帶好處，就是代理人自己也能去看這些東西，這對打造更有用的系統來說非常有幫助。我們也希望它是反壟斷的，意思是打造能對抗集中權力的工具，讓每個個人能真正掌控自己的技術與生活。

我們不希望所有資料被鎖在某個我們無法存取的孤島裡，我們不希望價格突然被調漲，而我們卻對此無能為力。最後，我們希望打造有道德的軟體。我覺得大家有點忘了，軟體的意義是要在現實世界裡做成一些事情。遞迴式自我改進固然很好，但說到底，我們到底是在改進什麼？我們想打造的，是對我們自己好、對這個世界也好的東西。所以龐克軟體也有其道德的面向。那這在實務上會是什麼樣子？在實務上，要打造這些代理型 AI 應用與系統，需要很多東西堆疊起來。

所以有一整套技術堆疊，而我們希望每一層都是開放的。從最底層開始，我們希望基礎設施是開放的，像 Linux、像 Docker、像 SSH——我們有非常龐大且豐富的開放原始碼軟體生態系可以運用。我們希望推論是開放原始碼的，我們也希望模型是開放原始碼的，像 GLM 或 DeepSeek，或像 Nemotron 或 Inkling 這類模型。我們也希望代理人的執行環境（harness）是開放原始碼的，像 Codex、OpenCode、Cline、Goose。我們也希望在這些之上再多一層——我們要怎麼協調這些執行環境？怎麼協調代理人？像 Tmux、Herd、Cmux 這類工具，就是用來操作多個代理人、讓它們彼此溝通協調，並用這些較小的元件組出更大系統的方式。

最後，我們希望有頂層的東西，能運用這些代理人，最終真正做出一些有用的成果。所以今天我們要來看三個我們目前在 Imbue 正在進行的專案。下面兩個叫做 Manager，還有一個專門給 Manager 用的外掛叫做 Manager Donate，第三個是我們正在打造的一款應用程式，叫做 Mines。Manager 是一個開放原始碼工具，可以用來協調代理人，今天就能免費取用，已經上線，也在 GitHub 上。Manager Donate 和 Mines 目前還在測試階段，如果你想要取得存取權限，直接寄信給我們就好，我們很樂意提供。事實上它們技術上已經是開放的，你可以自己去找到，但如果你寄信給我們，會更清楚該怎麼用。

好，第一個是 Manager。Manager 的重點在於把 AI 模型與運算供應商商品化，我的意思是，讓你可以使用任何你想要的 AI 模型、任何你想要的運算供應商。核心概念是把 AI 代理人變成打造更大系統的一個組成模塊。如果你能讓它們幫你完成整個任務，你就能建構出一個更大的系統，而不會被綁死在只能用 Codex 或只能用 Claude Code 上。所以 Manager 的想法，就是不再要求 AI 代理人一定要是互動式的。我們不希望你坐在那裡，一直按「是」，來確認要不要執行這個超大的 bash 指令，那其實蠻浪費你的時間的。我們希望你能去思考，怎麼用能夠組合、堆疊成更大系統的方式來執行這些工作。

這裡是 Manager 的概觀，以及它的運作方式。它是一個很薄的中介層，介於你的應用程式、任何執行環境（harness）、以及任何運算供應商之間。所以你可以用 Codex、Claude Code，隨便你，也可以用 AWS 或 GCP，隨便你，但重點是你不用去煩惱這些。取而代之的是，你只需要一個非常簡單的命令列工具，你可以打 manager create 來建立並啟動一個代理人，或者告訴它要在哪裡啟動，或者給它取個名字，或者告訴它要用哪個執行環境。你仍然可以傳入額外的參數，就像倒數第二個範例那樣，manager create 可以指定要用 Opus，或者你也可以傳訊息給它。所以 Manager 的重點其實在於，你還擁有這些其他的基本操作。

你可以用像 manager message 這樣的指令，傳訊息給代理人；或者用 manager transcript，看你和代理人之間已經傳過的所有訊息，這在不同的編碼代理人之間是統一存取的。所以你不用去煩惱說，Codex 的格式跟 Claude Code 的格式不一樣這種事，你完全不用管，Manager 會幫你處理好這一層互通性。運算資源也是同樣道理。你還有像 manager list 可以看你所有的代理人，manager connect 可以直接連上某一個。當你呼叫這個指令，你就直接進到終端機裡，就像是原生在跑 Claude Code 一樣，但實際上那個 Claude Code 可能是跑在 AWS 上、跑在 Modal 上、或是跑在本機上。

這都無所謂，你可以直接跟它互動、讓它繼續執行、斷線離開，一切就搞定了。你還有像 manager weight 可以組合出其他更大的東西，還有 manager snapshot。這其實就是一整套工具箱，讓你能打造出更高層級的系統，還有更多指令，你可以自己上網去看完整清單。那如果我們用龐克軟體的標準來打分數，這算是好的龐克軟體嗎？我覺得算，畢竟就是我照這個方向設計的。它個人化嗎？是的。Manager 一個不一樣的地方在於，它沒有服務端，我們不是要賣你一個 SaaS 產品，沒有遠端資料庫，一切都在本機端。它每次執行時，只會單純去問：AWS 上有沒有任何東西？

本機有沒有任何東西？好，這樣就好了。所以你可以完全掌控這一切，做外掛、改設定都很容易，全部都是由你直接掌控的，完全去中心化、完全屬於你，而且是 MIT 授權。我認為它相當程度上是反壟斷的，因為它試圖把 AI 模型與運算供應商商品化，試圖讓你不會被鎖死在他們那種垂直整合的生態系裡。而且它至少也帶有一點道德性質，因為它試圖直接賦權給你這個個人。好，我們今天要看的第二個東西，是 Manager 的一個外掛，叫做 Manager Donate。要做新的外掛非常容易，我們做這個外掛，是為了讓你能輕鬆把用不完的 token 捐給科學研究。

我們在這裡要解決的問題是：你其實沒有完全用滿你的訂閱額度。理論上，你的訂閱可能一個月大概花 100 美元訂閱 Claude Code，如果你把它用到滿，等於在 API 上大概值 4000 美元，但你不一定每次都會用到滿。如果到了週末，你發現額度還沒用完，何不把這些 token 捐給某位科學家，讓他去做一些有用的研究呢？這就是這個外掛能做到的事，而且它是建構在 Manager 之上，這讓實際的實作變得容易許多。Manager 可以幫你在沙盒環境、或本機的 Docker 容器裡，執行科學家交付的任務，所以你不用擔心他們跑的是不受信任的程式碼。

它也能理解你訂閱額度的使用狀況，確保不會用掉你自己原本打算要用的 token。那如果用龐克軟體的標準來打分數，這有多龐克？我覺得它完全是個人化的，你可以精確控制自己想捐多少、不想捐多少、想捐給哪些用途等等；它完全去中心化，概念是科學家可以直接發布他們想做的研究，你的系統就會自動去把任務拉過來、算完、再送回去；它是完全開放原始碼的；反壟斷性也算有一點吧，我不太確定現在有多少壟斷企業在做開放原始碼、分散式的 AI 科學研究。

至於道德性，嗯，為科學做出貢獻，我想我們大部分人都會覺得這是件好事。那第三個要看的東西，是我們建構在 Manager 之上的應用程式，這個比較是給一般人用的，而不是給軟體工程師用的。Mines 是一款應用程式，設計理念是要成為個人智慧，有點像是一台個人電腦。核心概念是，你讓語言模型跟它所建立的軟體一起運作。所以不是像在 Replit 那樣建立一個應用程式，然後部署它，還要有資料庫、要有正式環境、要有資料庫遷移，那些其實都只是一堆雜訊，是你在做個人儀表板或每天執行的一個小腳本時，根本不需要的那種額外複雜性。
