很好，接下來談談 NLIP 規格，它刻意設計得非常精簡。如果你看訊息模型，會發現它是一個輕量級的 JSON，總共只有五個欄位，其中三個是必填。你有 content（內容），這基本上是一個輕量級的 JSON 封套，裡面裝著要交換的資訊。格式（format）欄位讓你指定內容是文字、結構化資料還是二進位；接著 subformat（子格式）則是進一步的細化，如果是文字，就標明是哪種語言，如果是二進位內容，就標明編碼方式。另外還有兩個選填欄位，用來提供傳遞提示（passing hint），你也可以在子訊息裡放更多附加內容。核心的資料模型基本上就是這樣。

就是這五個欄位。如果拿來跟一些比較常用的協定比較，例如 A2A 或 MCP，光是欄位就有 60 到 99 個，完整資料模型甚至到 166 到 480 個欄位。從這個角度來看，NLIP 非常輕量，而且在標準傳輸層上實作起來很簡單。它有針對 HTTP、WebSocket、AMQP 的綁定（binding），這些都寫在 ECMA 規格書裡，你可以到 GitHub 頁面上取得。而且它從設計上就內建安全機制，這是強制規定的。你有三種安全性設定檔（profile），從基本到嚴謹的企業級都有，除了傳輸層的安全之外，還處理了各種 AI 專屬的風險。現在，NLIP 可以用兩種模式跟各種單一廠商的協定互通。

第一種模式是：NLIP 作為北向（northbound）API，單一廠商協定作為南向（southbound）API，中間透過翻譯代理人（translation agent），也就是 LMPod，來做兩者之間的轉換。第二種模式 B，則可以跨多個領域互通，每個領域裡都可以有多個代理人，各自用不同的代理人框架、以自己的語言溝通。但只要它們具備 NLIP 感知能力，彼此就都能溝通。這是一個非常強大的特性。目前已經有多家公司與大學開發出多個概念驗證（proof-of-concept）應用，橫跨電信、購物、永續發展、多模態客戶服務等各種領域。其中不少也都公開在專案頁面上。

那我就深入談一下客戶服務這個案例。在這個情境裡，客戶提交一個語音請求，也就是一個查詢，這是一段音訊，接著會用 NVIDIA ASR 這個語音轉文字模型把它轉成文字。然後我們透過 HTTP 傳輸 NLIP，把這段資訊送到頻道推薦器（channel recommender），它會找出跟這個查詢最相關的 subreddit 頻道，接著同樣透過 HTTP 上的 NLIP，把資訊送到搜尋代理人，由它從這些頻道裡挑出最相關的主題、排序後回傳給客戶。整體來說，客戶的查詢會從 Reddit 上找出最相關的主題，客戶就拿到這些回應。我們把這個工作流程裡的 NLIP 跟 A2A 做了比較，使用非常相似、對稱、一致的計時測試框架來比較 NLIP 與 A2A，並用了三個 A2A 的變體版本，同時也做了階段層級的計時儀器化，也就是訊息建立、連線建立、傳送這三個階段，藉此真正了解時間都花在哪裡。

而總延遲基本上就是這三個階段時間的加總。我們用了兩台機器、兩組資料集，裡面包含了好幾筆客戶查詢。

在這兩個階段裡，各查詢的平均總延遲，你會看到 NLIP 是藍色的，右邊則是 A2A 的各種變體，從 SDK 版、快取最佳化版 A2A，到輕量級 Python 版 A2A。你會發現，A2A 精簡版本的表現在這裡確實有所體現。當然，我會說這些都還是初步實驗，還可以做更多更複雜的工作流程與實驗，這也是我們接下來想做的事。如果你也有興趣參與，那就太好了。不過這至少能讓大家感受一下，這是一個非常輕量的訊息封套。對於實務工作者來說，關鍵問題會落在：什麼時候該用哪種協定。當你的使用情境需要異質協定互通性、語意彈性，或跨協定中介（cross protocol mediation）時，可以選擇 NLIP。

而當你有治理與稽核需求、以任務為中心或長時間執行的工作流程、嚴格的綱要（schema）規範、確定性執行時，就選 A2A；如果是混合工作負載，甚至可以選擇混合方案，在協調層用 NLIP，在治理層用 A2A。這些都是我們根據實驗與評估結果，正在整理的各種建議準則。但這裡最重要的一點是，協定的選擇應該由工作負載的特性來決定。目前我們有好幾種協定，基本上都是長尾協定，也有越來越多針對特定領域的協定被引入，像是支付、購物等等。所以問題在於，我們要如何跨這些協定運作、以互通的方式溝通。

而這正是 NLIP 派上用場的地方。

總結一下，NLIP 本質上是一個以標準為基礎的語意協定，用來連接客戶端與代理人，並橋接不同的代理人協定。它簡單、開放、輕量、中立，你可以把它想成是「意圖的 HTTP」，是為智慧時代打造的協定。在初步實驗中，我們觀察到它在訊息建立與傳輸階段都相當有效率。對實務工作者來說，可以根據代理人工作負載的特性來選擇是否採用 NLIP。你可以在專案頁面上找到 NLIP 的詳細資訊，它也已經整合進 AG2 框架，這個框架每天下載量高達數萬次，一個月下來可能上看百萬次。如果你有興趣、想給我們回饋，我們永遠歡迎。
