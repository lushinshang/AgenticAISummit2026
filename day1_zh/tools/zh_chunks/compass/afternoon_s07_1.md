## 03:20 PM 第 3 場：基礎能力 - 精選演講

**講者**
- Doga Kerestecioglu（微軟首席應用科學家）—— 正念代理人：受人類啟發的長時程任務記憶

好的，謝謝這場精彩的工作坊。接下來我們繼續進行演講場次。這位是 Doga Kerestecioglu，微軟首席應用科學家，講題是「正念代理人：受人類啟發的長時程任務記憶」。

沒關係，不用擔心。大家好，很高興來到這裡。我來自微軟 Fabric AI 團隊，今天要跟大家分享我們在即時智慧（real-time intelligence）領域中，針對長時程代理人（long-running agents）所做的工作，我們從人類自身的記憶方式得到啟發，藉此改善代理人的記憶能力，讓它們能更好地完成任務。在我們所處理的領域中，長時程代理人通常需要存取大量資料，尤其是大量的串流資料；為了說明我們面對的問題以及這套方法背後的動機，我想先對比一下人類儲存記憶的方式，跟我們目前為代理人設計的方式有何不同。

人類的記憶有儲存上的限制，也正因為這個限制，反而讓我們更擅長萃取記憶的精華。舉例來說，我最近在歐洲搭火車，看著窗外掠過一望無際的田野，也許還看到風車、正在吃草的動物，但我們並沒有能力記住每一根草或每一個細節。我們擅長的是把這些資訊萃取出重點，只記住可能與我們相關、有趣的部分，這其實是演化讓我們變得擅長的能力。但如果換成代理人（agent），它們並沒有儲存空間限制這個問題。

我們可以記錄每一則資訊，成本相對低廉，也可以記錄每一筆軌跡（trace）。我們的作法是擷取、檢索，然後通常會摘要並保留摘要。久而久之，我們手上會有一層又一層摘要的摘要，這種做法在多數情況下運作得不錯，直到檢索時要找非常特定的資訊時就會出問題。但就我們正在處理的案例而言，我們希望代理人能處理這些大量的資料集，而且希望它們是主動積極（proactive）的。

因此我們著手為代理人建立一套「記憶生命週期」，作為一個回饋迴圈。這套系統一開始是擷取（ingestion），也就是把可觀測性基礎設施（observability substrate）中的所有資料匯入進來；接著是整併（consolidation），這個概念有點類似睡眠，我們會去重、合併，把匯入的所有記憶整併成候選記憶。這裡的重點是，雖然這個概念類似人類，但我們所處理的代理人，其整併週期是依領域而定的，不一定是以時間為週期。不知道在座還有多少人記得，稍早有人在做一個關於 F1 賽車的代理人，如果代理人處理的是一級方程式賽事，比賽期間所擷取的遙測資料（telemetry），跟賽後、非比賽週的資料會非常不同，整個賽季下來又會更不一樣。所以整併不一定要每天做一次，而是要依照某種節奏，分批次處理。

接下來是遺忘（forgetting），其中包含衰減與干擾。這裡的想法是，當我們有了這些整併後、已經穩定下來的候選記憶，我們要確保最後留下來的是重要的事情，而不重要的內容則盡可能被遺忘，或至少大部分被遺忘。

接下來的階段是檢索（retrieval）。在檢索方面，我們採用的是混合式做法：一方面，我們把已知領域的記憶儲存在冷儲存（cold storage）中，並整理成圖（graph）；另一方面也有即時資料不斷進來，我們希望代理人能同時存取串流資料和較穩定的儲存內容，並判斷當下該用哪一個記憶最合適。這就帶出了回饋迴圈：在檢索時通常會出現衝突，也許發生了新的事件，跟已經在冷儲存中穩定下來的記憶產生衝突。這時候就需要「成熟化」（maturation）與「再整併」（reconsolidation），因為我們不希望不斷把新記憶加進圖裡，讓圖變得很難檢索。所以你必須判斷：要更新圖中的既有實體、因為出現重要新資訊而新增一個實體，還是因為即時資料有誤而直接捨棄它。接下來我想談談，這些環節其實都各自是獨立的元件，各自需要不同的最佳化方式。

接下來我想談談我們是如何評估（eval）這套系統的，以及背後的思考方式。這裡有兩個案例，分別評估「上限」與「下限」，也就是最佳情境與非常艱難的情境。左邊是一個留存度基準測試（retention benchmark），比較具有確定性：在這個案例中，系統對於哪些資訊重要有明確的標籤。我們在這裡想最佳化的是整併的頻率，以及該用什麼樣的節奏來整併。這個結果會依領域不同而變化，但大致上在每次約 500 筆事件時開始趨於穩定——不好意思，應該是每次 200 筆事件。字有點小不好看清楚，是 200 筆事件，並搭配一個精確度指標：如果我們適度遺忘，精確度反而會提升。所以我們就是在檢驗：整併多少內容，能得到最好的精確度？

整併的頻率是多少、遺忘要疊加多少，這是第一個案例。接下來第二個案例，我們使用一個以 LongMemEval 為基礎的檢索基準測試，觀察的是：我們應該壓縮多少？在不造成破壞的前提下，最理想的儲存空間大小是多少？這個測試的資料是對話內容，我們並沒有關於哪些內容重要的標籤，這對我們正在做的工作來說並不是理想情境，因為我們設想的是那些重複執行特定任務的領域專家，理論上是可以學到什麼是重要的。但即使在這種情況下，我們依然可以做最佳化，在壓縮程度與準確率之間存在一個權衡（trade-off）。

綜合來說，對於我們正在做的這類記憶工作，需要三種評估方式，各自關注不同的重點。第一種是留存度（retention），可以用確定性的方式快速評估：如果你在建構記憶系統，想確保保留下來的是重要資訊，你能否確保留下來的內容確實重要，這需要標籤，我們也投入不少心力在如何取得更好的標籤上。第二種是檢索（retrieval），假設你已經建好一套良好的記憶系統，接下來就要看你從中檢索的效果如何，能不能在你建的這套完善系統裡，找到你要找的記憶；因為如果記憶難以導覽、檢索也做不好，那麼即使系統再完善，也只是必要條件而非充分條件，所以你需要有良好的檢索能力。最後，對代理人來說，真正要看的是任務完成度評估（task completion evals），這是最重要的一項，因為它最貼近使用者的實際感受。你也許給了代理人最好的記憶，但依照你的 harness 如何把記憶呈現給代理人，代理人也可能選擇忽略它，依然無法完成任務。這也是成本最高的一項評估，因為對長時程代理人來說，建立與執行這類評估相當昂貴，但卻是最重要的。

針對每一個環節，我們都聚焦在這三件事情上。簡單總結一下：日誌（logs）不等於記憶。我認為未來的走向是，對長時程代理人而言，你需要確保代理人能取得的記憶不只是單純的軌跡紀錄。而為了在資料量龐大的情況下維持效率，你必須想清楚該如何判斷哪些內容值得保留。另外一個重點是，領域（domain）非常重要，這類系統的領域通常需要事先宣告；能否在執行時期做得好，取決於你事前是否已經準備妥當，否則會影響代理人執行的效率與準確度。

談到接下來的工作，我們正與微軟 Foundry 團隊合作，在 StateBunch 上進行端到端的評估，同時也在領域學習與圖本體論（graph ontology）方面做進一步研究，因為我們發現，除了前面提到的這些元件之外，圖結構與本體論的設計方式，對準確度也有很大的影響，所以我們也持續投入研究。以上，非常感謝大家，期待會後與各位交流。

接下來是 Ian Fischer，Poetiq 共同執行長，講題是「從最佳化視角看遞迴自我改進」。

好的，大家好，我是 Ian Fischer，Poetiq 的共同創辦人暨共同執行長。如果大家還沒聽過 Poetiq，我們是一家大約一年半前成立的新創公司，整個公司完全專注在遞迴自我改進（recursive self-improvement，RSI）上，也就是打造能夠自我改進的 AI。在過去不到一年的時間裡，我們從零開始，做出了一套能自動在多項重要公開基準測試上取得最先進成績（state-of-the-art）的系統。我們團隊有十位科學家與工程師，多數來自 Google、DeepMind、Apple、Microsoft、Amazon、ByteDance。我們早期在推理與知識萃取方面已經取得一些成果，在這些項目與程式撰寫（coding）上都拿到了最先進的成績。接下來就讓我深入說明。

我想先仔細定義一下什麼是 RSI。其實這應該很簡單，只有三個字母，而真正在起作用的是其中兩個。「遞迴」（recursive）指的是每一步的新改進，會驅動下一輪的改進；「自我」（self）指的是這個系統改進的是自己，而不是其他目標——這一點看似顯而易見，畢竟大家都在做某種形式的改進，但「遞迴」與「自我」必須成對出現，如果缺少任何一個，其實就不算真正做對了。我在這裡之所以有點吹毛求疵，是因為一般人使用 RSI 這個詞時，定義往往既太寬鬆又太嚴格。有些人把單純的標準迭代改進迴圈也稱為 RSI；另外也有人認為，只有在改進大型語言模型的參數時才算是 RSI，這又太嚴格了，因為智慧系統中還有很多其他部分，都能有效地被改進。

那 RSI 為什麼重要？我們認為 RSI 是 AI 研究中最重要的前沿領域，因為真正的 RSI 系統的改進會不斷複利累積，這會比人類主導的改進方式更快達到超級智慧（superintelligence），原因很明顯：人類在改進模型的同時，自己並不會無止盡地變得更聰明，但 RSI 系統可以。接下來我簡單談談這個領域的全貌：我們可以用兩個軸來劃分 RSI 的做法。Y 軸從上方的「便宜」到下方的「昂貴」；X 軸從左邊「其實根本不是 RSI」（例如標準的迭代最佳化方法）到右邊「真正的 RSI」。右上象限是個不錯的位置，我們當然把 Poetiq 放在那裡，但這並不是隨便講講的。

我們把自己放在那裡，是因為我們的迴圈確實會複利累積，這是貨真價實的 RSI。而且 RSI 的每一步只需要一次推論（inference）成本，而不是一次 LLM 的訓練成本。右下象限是資金最充裕的一群，這也是大家談到 RSI 時通常想到的那種——以 LLM 為中心的視角，Anthropic、OpenAI、Google 都在這裡投入大量心力，這些做法大致上也是貨真價實的 RSI，只不過每一步都需要從頭訓練一個 LLM。右上象限還有幾個鄰居，同樣是貨真價實的 RSI，成本也很低，但範圍比我們的做法窄一些，像是 Darwin Gödel Machine 跟 CICA，這兩者主要都聚焦在程式撰寫（coding）上。

而 MiniMax 這套 harness，則是用它自己產生的部分資料來訓練。如同我剛才提到的，這整個版圖大致可以分成兩塊：下半部是以 LLM 為中心的做法，主要聚焦在改進特定的 LLM；上半部則是更偏向系統導向的做法，把 LLM 視為更大系統中的一個元件，而這整個系統才是要被改進的對象。從「以 LLM 為中心」轉為「系統導向」的視角，會打開很多原本會被忽略的改進可能性，而且這類做法通常也更快、更便宜。接下來我想談談兩個相當知名的做法。第一個是 Anthropic 最近發表的〈自我建構的 AI〉（AI that builds itself）一文中描述的方式：拿一個版本的 Claude，放進 Claude Code 裡，然後由人類加上 Claude Code 一起改進 Claude。

這其實是「部分的 RSI」。Claude 顯然既是被改進的對象，也是負責改進的系統的一部分，但當中也有人類參與，所以我不太想把它算進去，Anthropic 自己好像也沒有把人類算進去。另一邊，還有一個常見的做法叫做「自動化 AI 科學家」（automated AI scientist），這也類似所謂的自動研究（auto research），這種做法通常算不上是 RSI。這裡面有好幾個節點各自負責不同的工作，但基本流程是：系統產生一個假設，接著實作這個假設，然後進行測量，再寫成一篇論文，把論文放回某個知識庫中。

而這通常不會針對系統自身的某個部分下手，所以其實稱不上是 RSI。不過我們可以把這兩者都改造成純粹的 RSI 系統。以 Anthropic 的例子來說，只要把人類拿掉就可以了，他們似乎也暗示過未來會走向這個方向，這也許正是他們有點擔心的地方。至於 AI 科學家，修正方式也很簡單：只要把你在 AI 科學家迴圈中使用的 LLM 也當作改進目標即可。當然，這樣做的成本會比一般人做自動化 AI 科學家貴上許多。那 Poetiq 到底在做什麼呢？我們做的叫做「自我最佳化的最佳化器」（self-optimizing optimizers）。這是什麼樣子呢？我們從一個通用最佳化器（general purpose optimizer）開始，所謂通用最佳化器，指的是不依賴任何專門訊號（例如梯度）的最佳化器。

它只需要來自最佳化目標的可衡量回饋。這比爬山演算法（hill climbing）之類的黑盒最佳化器還更通用，因為回饋不必是量化的。有了這個通用最佳化器之後，我們就拿它來最佳化某個對象：設定一個最佳化目標，它會回饋訊息給最佳化器。如同我剛才說的，這裡的回饋可以相當多元，可以是準確率、成本這類標準做法，也可以是評分準則（rubric）評估或推理目標這類比較特殊的回饋。有了這兩塊之後，這顯然還不是 RSI，只是標準的迭代最佳化而已。但我們有這套通用最佳化器的框架，接下來就可以把它應用在最佳化器自己身上。

於是，現在這個最佳化器，最佳化的是「另一個正在最佳化目標的最佳化器」，這就是 RSI 了。要讓最佳化器能夠自我最佳化，其實只需要兩個條件：它必須是通用最佳化器，而且這個最佳化器必須能提供關於自身表現的回饋。因為我們一開始用的就是通用最佳化器，而每個最佳化器都能做到這件事，所以這裡並沒有問題。但我要說清楚，這跟直接說「最佳化器就是 Adam 或 SGD」完全是兩回事，那樣是行不通的。這就是我們所謂的「Poetiq 元系統」（poetic meta system），它是 RSI，而且我們用它來最佳化一切。元系統最佳化的每一項任務，都會幫助它進一步最佳化自己，讓它變成更強大的最佳化器。

而且，正因為它是通用最佳化器，我們可以把它指向元系統自身的任何一個部分，也可以指向任何其他可衡量的任務，例如一開始展示給大家看的那些基準測試，或是客戶資料等等。談到實證結果，我們最近的實證成果中，有一篇部落格文章指出：對我們來說，「基準測試已經沒有意義了」（benchmarks are dead）。這句話真正的意思不是說基準測試沒有用，而是說，當你擁有一套真正能遞迴自我改進的系統時，靜態的基準測試價值就相當有限了，因為我們幾乎能在每一個測試過的基準上，全自動達到最先進成績（SOTA）。

再強調一次，是全自動完成的，也就是零人工介入，而且通常速度相當快。具體來說，這裡有一張結果表格。其中一個有趣的地方是，在這些橫跨許多我們從未處理過的領域的基準測試中，有一半我們是用比先前 SOTA 保持者（通常是 Fable 5）更舊、更便宜的模型就達到了 SOTA。那接下來要做什麼呢？現在我們不再把重心放在基準測試上，而是在跟多個領域的早期客戶合作。我想留給大家的觀點是：AI 領域下一個階段性的躍進，將會來自一套能夠自己發明自己的改進方式的系統。

在 Poetiq，我們刻意為了這個階段性躍進撒下一張很大的網，用最佳化的視角來看待 RSI，並用它來最佳化一切，包括最佳化器自己。謝謝大家，我們也在徵才。

接下來是 Yu Su，NeoCognition 執行長，講題是「智慧 + 持續學習 = 專業知識」。

測試一下，麥克風沒問題。好，今天這場演講會偏向概念性，我會談三個概念：智慧（intelligence）、專業知識（expertise），以及持續學習（continual learning）如何連結這兩者。我認為這或許是我們今天必須思考的最重要概念性問題之一，也能幫助解釋許多我們在 AI 前沿觀察到的怪異現象。第一個觀察是：AI 已經變得非常聰明了。

今天早上，OpenAI 才剛宣布解決了另外十個重大難題。但另一方面，AI 在企業界的普及速度似乎遠比大家預期的慢，我們也看到大量「前線部署工程師」（forward-deployed engineer）與部署顧問公司如雨後春筍般出現，協助企業導入 AI。但如果這些 AI 真的這麼聰明，為什麼還需要 FDE 來幫忙部署呢？它們不是應該自己部署自己嗎？人類做一份工作也不需要 FDE 來教我們怎麼做。所以中間到底缺了什麼？另外，如果我們看 AI 產業鏈中的價值分配，會發現九成的價值都流向基礎設施層與模型層，應用層拿到的不到一成，而且經常還是負毛利在經營。

為什麼會這樣呢？這顯然不是一個穩定的生態系均衡狀態，那我們該如何解決？我希望這場演講能幫助大家理解今天觀察到的這些怪異現象。好，顯然目前這一代的代理人，我們稱之為「語言代理人」（language agent），因為用語言來推理與溝通正是它們的定義性特徵。而它們已經找到了第一個大眾市場，很明顯就是程式撰寫（coding）。要看到這一點，最好的方式就是看 Anthropic 的營收成長曲線，大家應該都看過這個很神奇的故事。但程式撰寫之所以是第一個大眾市場，很大程度是因為它本來就是一個「語言特權」（language privileged）的世界，一切早已用符號方式表達出來，而且被紀錄與維護得非常好。

這讓程式撰寫成為語言代理人的完美舞台。但如果我們離開這個符號特權的程式世界呢？結果就沒那麼理想了。我記得 Netland 專案的報告指出，企業導入 AI 時遇到很多問題，當然這是去年的報告，那個 95% 的數字大家可以有不同看法，但我認為方向上是正確的，反映出實際的困難程度。接著我們看到代理人各種各樣稀奇古怪的失敗模式，嚴重到 Andrej Karpathy 去年在 .cash 播客上主張，2025 年不會是「代理人元年」，而會是「代理人十年」的起點。他特別提到電腦操作（computer use）與持續學習方面的挑戰。

我認為我們現在觀察到的，其實是「莫拉維克悖論」（Moravec's paradox）的現代版本。回想一下 1980 年代最初版本的莫拉維克悖論，大意是說：對 AI 而言，難的事情反而容易，容易的事情反而難。AI 特別擅長數學、程式撰寫這類符號推理任務，但要學會人類覺得毫不費力的事情卻非常困難。在 80 年代，那指的是移動能力與知覺；而現在，我們則是在日常的數位工作中看到類似的困難。這是為什麼呢？我的假設是這樣的：如果你觀察現代社會，會發現它其實不是單一統一的世界，而是由成千上萬個「微觀世界」組成。每個職業都不同，每間公司都不同，每間公司之所以特別、之所以存在，正是因為它與眾不同。

每個環境都有自己獨特的「局部物理法則」：結構、限制、可供性（affordance）、動態變化。這種異質性與動態性太強，任何試圖把它壓縮成單一靜態表徵的靜態模型都無法勝任。所以你必須在工作中持續學習，才能形成專業化的專業知識（expertise）。這就帶到下一個主題：智慧（intelligence）與專業知識是不同的東西。談到智慧，我們聚焦在大型推理模型（LRM）的脈絡下，也就是 LRM 所展現的那種智慧，本質上是解決問題的能力：給我問題陳述、給我脈絡，它就能在這個巨大的解答空間中推理，甚至可能拉出上百個子代理人，試著幫你找出解答。但專業知識不一樣，專業知識是一種累積且情境化的能力，是能在特定環境、特定工作中，可靠、有效率、有判斷力地展現出真正實務表現的能力。希望透過這樣的對比，兩者的差異已經很清楚了。那專業知識裡到底包含什麼？如果我們參考認知科學的文獻，可以得到一些啟發。

基本上，當我們在工作中學習、形成專業知識時，其實是一個不斷建構關於這份工作、這個領域的新心智表徵（mental representation）的過程，這會以多種方式展現出來。舉例來說，如果你在看一份很長的當機系統錯誤報告，專家跟新人看到的東西會非常不一樣：專家能很快鎖定可能出錯的地方，也能看見深層結構，而不只是表面的樣式（pattern）。專家知道一切都是有條件的：每一條規則背後都有一大堆需要學習的前提條件，規則何時成立；但你同時也要學會有哪些例外情況，可以違反規則來對應現實。最後，我們最近常談到的判斷力與品味，也都是來自專業知識。從這個角度來看，專業知識其實可以說是一種「世界模型」（world model），是那個微觀世界的模型，會以許多不同方式展現出來，成為我們知覺、推理與決策的基礎。接著我們可以進一步比較這兩者，但礙於時間，我認為最有趣的比較是：智慧——至少是我這裡所談的這種智慧——本質上是「昂貴」的。

智慧會即時尋找脈絡、擴大搜尋範圍，正因為它無法從過去累積經驗，所以會消耗大量的 token。像我們在 NeoCognition，光是 token 就燒掉了好幾百萬美元。但專業知識本質上是「收斂」的，它是一個不斷形成捷徑、形成該領域有效結構的過程，能縮小你的搜尋過程與搜尋空間。好，接下來我要談持續學習（continual learning），但因為只剩幾分鐘了，我得講快一點。「持續學習」是一個很容易混淆的名詞，我先試著給出一個統一的定義：我認為持續學習，是把經驗適應性地壓縮成可重複使用的結構，以供未來行為使用的過程。

這其中的四個要素都非常重要。當你談論持續學習，或是看到某項持續學習相關的研究時，你都需要弄清楚這四個要素分別指的是什麼：談的是哪一種經驗、如何壓縮這些經驗、壓縮成什麼樣的結構，以及如何用這個結構來指導未來的行為。而這裡的「適應性」非常關鍵：你過去壓縮經驗的方式，應該會決定你未來壓縮經驗的方式。接下來，我認為是這場演講中最重要、也最有趣的部分：智慧、專業知識與持續學習三者之間的關係。如果把智慧當作 X 軸、專業知識當作 Y 軸，你會發現這兩者在很大程度上是互相獨立（orthogonal）的。

你可以得到智慧程度更高的模型，但如果沒有持續學習，它就會變成我所謂的「世界上最聰明的生手」（world's smartest novice），只能靠純粹的智慧蠻力硬解每一個問題，這也是為什麼大家的 token 帳單都在暴增。不同的持續學習演算法，本質上決定了你學習曲線的斜率。所以如果目標是打造非常強大的持續學習演算法，讓我們得到非常強大的專家型代理人；順著這個思路推演下去，我認為最有趣的未來，是我所謂的「以有限的智慧，換取無限的專業知識」（unbounded expertise from bounded intelligence）。如果智慧存在一個門檻——姑且稱之為「逃逸智慧」（escape intelligence）——一旦跨過這個門檻，再搭配強大的持續學習演算法，我們就能得到近乎無限的專業知識，或者至少足以應付這個世界上九成、九成五工作所需的專業知識。

如果這件事成真，就意味著市場會出現非常明顯的分化：前沿模型廠商會持續打造更聰明的模型，這些模型也會有許多應用場景；但對於另外那 90% 到 95% 的工作來說，我們也許不需要更聰明的模型，也許現有的模型就已經夠好了，真正欠缺的只是持續學習。這將會是市場上一個非常有趣的動態發展。
